# 回响公共事实回答与实时查询设计

建档：2026-10-04；开发验证跨日至2026-10-05。问题编号：DJ-ECHO-PUBLIC-FACTS-20261004。

本方案修复私人记忆约束扩大到所有事实导致的拒答，并分两步补齐公共信息能力。先验证公共常识与日期，再实施实时天气和周边查询。阶段结论及原始失败都写入实施记录，不将本地或协议验证等同真机通过。

## 一 当前证据与目标

后端 main.py 的 Live 基础角色与 formal_memory_conversation_snapshot.py 的绑定角色，都限制所有事实只能来自正式记忆。文字 DeepSeek 已有一般问题分支，但 family 被一律判为必须检索私人记忆，会在无命中时提前拒答。目前未核实当前 SpeechEngine 模型可用的联网搜索配置，不能宣称仅改提示词就具备天气和附近商户能力。

用户期望公共常识正常回答；日期取可靠时钟；天气和店铺依据实时资料。个人或家人历史不编造，当前明确提供的信息只能作为本轮语境，不冒充已确认记忆。外部资料和助手建议不得作为用户经历入库。

## 二 影响范围与不变约束

| 范围 | 拟变更与风险控制 |
| --- | --- |
| Live 角色绑定 | 将限制限定私人事实；时间信息计入原8192 UTF-8字节预算，继续整条选择正式事实，保持身份、权限及快照哈希绑定 |
| 文字回答 | 同样区分公共与私人问题；家人权限仍先验证，只放宽明确公共问题，不改变模糊家人问题的保守判定 |
| 时间上下文 | 服务器时钟为时间源，iOS只上报IANA时区；无效/缺失时区显式使用UTC，不默认用户在某城市；Live标明会话开始参考时间，不冒充持续更新的时钟 |
| 第二步联网入口 | 优先验证当前火山原生链路；凭证留服务端，禁止写入App、返回票据或日志；未配置时降级诚实回答，不阻止普通Live |
| 查询资料 | 缺位置先问，不拿旧住址作当前定位。仅查询必要公共地点/关键词，不外发整份个人记忆；资料为数据而非指令 |
| 保存及音频 | 不修改正文采集、会中整理、发布、审核、正式写入、自动状态更新、开麦时限、PCM/播放器、同音色告别和十分钟自然收尾逻辑 |

本轮开发不部署、不安装、不操作生产或历史数据、不提交推送。可用既有授权的合成供应商诊断，不读取个人记忆；每步最多8次Live输出和8次DeepSeek请求，无无限重试。外部账号权限/密钥缺失如实记为BLOCKED，不以模拟结果替代。

## 三 第一步 常识与可信日期

1. 统一规则：一般知识可用常识；私人历史限授权记忆，本轮明确自述可用于自然回应，但不视作正式记忆；公共知识不能反推私人经历。
2. 同时修正两处Live角色。文字family仅对明确公共知识/日期问题放行；其他私人/省略问题仍走现有记忆限制，访问授权不放宽。
3. iOS在两类请求传递时区，服务器生成当前日期、星期、时区与采样时间；拒绝把客户端传入的日期当可信时间。文字每次请求更新；Live每次新会话更新。
4. Live时间为会话开始时参考值。对会中跨日或精确当前分钟，不能把旧参考值报成现在；先明确可验证边界，不改SDK会中消息顺序来强行刷新。第二步查询能核实时才扩展。
5. 未启用查询时，天气/营业/附近推荐明确需要实时核实，不因放宽而编造今天的温度、地址或营业状态。
6. 新规则和时钟在正式记忆数据区外，不能改变原始事实或存储投影。快照业务哈希与最终角色哈希保持各自职责，重复绑定不意外改变私人记忆身份。

### 第一步验收门槛

- 同断言修前失败、修后通过；Live最终role和文字入口都覆盖，不能只测字符串辅助函数。
- 空记忆常识/日期正常；个人未知经历仍拒绝编造；家人权限与私人记忆约束不变；询问位置与无实时数据降级明确。
- 时区日期跨UTC日、无效时区、用户伪造日期/提示注入；最终role预算/完整事实/哈希绑定回归。
- 真实火山和DeepSeek合成问题验证常识、日期、私人未知事实，核对实际文字/语音，不只HTTP成功。
- 受影响后端回归；本地默认API/Worker/隔离PG短A→逻辑十分钟→短B确认与重建回读。明确受控整理模型不是供应商语义证明。
- iOS请求与开麦/音频/告别/保存重点回归及构建；不改声音路径。真机和物理时长NOT_RUN。
- 上述本地及供应商门槛有实际失败或未满足时，不实施第二步产品代码；先收敛第一步或记录外部阻塞。

## 四 第二步 实时天气和周边查询

第一步达到门槛后开始。先核实当前模型1.2.1.1和SpeechEngine实际StartSession协议，不根据RTC/Ark文档推定相同能力。优先使用同一火山会话的官方联网搜索；官方支持与账号可用是两个独立条件。

1. 查天气先取得明确城市；附近店铺取得用户指定地点，暂不新增自动定位权限。若搜索只能得到网页建议，注明未核实营业/距离，不伪装地图实时POI。
2. 若原生搜索兼容且可控：服务端注入启用配置及密钥，保持现有音色、单次回答、打断及保存语义。对返回的来源/时间做可追溯记录，不记录密钥或整份记忆。
3. 若不兼容：必须先记录实测失败并补充本设计的后端查询协议和回合时序，不能在ASR后盲目追加RAG造成两次回答，也不换系统TTS兜底。
4. 文字通道使用同样公共信息边界及真实查询结果；DeepSeek本身不能靠提示词凭空联网。只检索必要公共查询，不发送整份generationContext。
5. 查询有界超时、无结果/限流/服务错误应正常回复“暂时查不到”，普通对话可继续；不得导致本场整理失败或无限重试。
6. 配置开关默认关闭；未配置时诚实说明，不能标天气/POI已实现。回滚只撤回公共查询/角色变更，无数据迁移。

### 第二步验收门槛

真实已知地点天气、周边推荐、缺地点澄清、未知商户/无结果、不确定营业信息及查询失败继续对话；公共资料不变成用户经历；混合私人偏好与公共建议不越权。必须验证实际查询证据及同音色非静音输出，模型口头说“我查了”不算查询证据。

重跑第一步回归及短A→逻辑十分钟→短B保存链。需要真机时另行执行短场门禁再做物理十分钟，并按已归档清理规则先保存本场证据、清理上一场测试记忆、验证清理后再开始；本轮不主动安装或启动手机。

## 六 第一步通过后的第二步接入核实（2026-10-05）

第一步门禁冻结后，使用现有语音凭证对原生1.2.1.1做一次合成StartSession探针，启用搜索但不提供搜索Key。供应商返回45000001：`volc_websearch_api_key is required`。这证明当前原生入口识别搜索配置且要求独立凭证，不证明已经获得搜索结果或完成SDK播放。

现有配置未发现独立联网搜索Key。已询问用户是否开通以及安全密钥文件路径，不要求在聊天中提供密钥。补核实际配置名后发现已有`AMAP_WEB_SERVICE_KEY`，目前项目用于行政区划查询；最初常见变量名检查漏掉了它。尚未核实天气/POI权限，也不能用它替代火山联网搜索凭证。

凭证具备后，第二步按以下边界实施和验证：

1. 搜索开关默认关闭，Key仅存服务器；不得进入客户端票据、提示词、日志、源码或文档。未配置时保留普通Live，不向供应商提交必然失败的启用配置。
2. 原生接入优先仅在后端转发层的StartSession配置帧加入搜索参数。验证协议头、帧长度、会话身份、压缩及JSON处理；保持其他事件和音频字节原样，保留模型、音色及已绑定角色文本与哈希。
3. 角色中宣告的查询能力必须与实际开关及凭证一致；不能先承诺联网再发现没有工具。文字通道按官方搜索HTTP协议独立取得结果，只传必要公共查询，保留来源、查询时间和有界超时，不传整份私人记忆上下文。
4. 凭证拒绝、无结果、限流和超时均需真实或受控证据；真实天气/地点结果与语音继续播放必须实测。供应商口头声称查询不算证据，未核实的限制保持未知。
5. 若原生搜索不满足需求，先补充替代接入设计和回合时序证据；不直接引入ASR后追加RAG的并发回答，也不更换语音链。

当前第二步为`SEARCH_CREDENTIAL_BLOCKED`：已做协议诊断，尚未编写第二步产品代码。既有高德配置作为备选线索保留，不据此宣布实时查询实现。

## 七 第二步本地实施细化（2026-10-05续办）

用户再次授权继续第二步。先完成无凭证可验证的默认关闭代码及回归；真实启用、验收仍需凭证，不把这个顺序调整解释为免除真实验收门槛。

- 配置：`ECHO_PUBLIC_SEARCH_ENABLED`默认false，`VOLCENGINE_WEBSEARCH_API_KEY`仅服务端；Live另有`REALTIME_VOICE_WEBSEARCH_ENABLED`默认false，避免文字HTTP已验收就自动开启尚未验收的原生搜索。两个开关均启用且有Key才宣告Live搜索。
- Live：角色能力说明在预算/哈希绑定之前生成；转发仅改1.2.1.1的StartSession JSON配置。校验原角色哈希、会话ID、帧长、JSON与有限解压；其余音频、打断及告别帧逐字节不变。缺配置完全沿用原转发路径。禁止客户端自行带入搜索Key覆盖服务端配置。
- 文字：初版仅受理明确公开地点的天气和周边商户请求；必要时明确追问城市/地标，不从正式记忆推断位置。混合私人描述只提取明确公共地点与类别；不能安全拆分时要求重述地点。一次回答最多一次搜索，已有回答修复复用同份查询结果。
- 查询使用官方API Key入口`https://open.feedcoopapi.com/search_api/web_search`；参考火山官方仓库`volcengine/mcp-server`的`api/api_key_auth.py`与`model.py`。仅发送公开地点、类别、日期限定，最多5结果，响应上限128KiB、整体等待最多6秒且不自动重试。请求失败和无结果只降级本轮公共信息回答。
- 返回公共资料与私人记忆引用分开；保留来源URL、标题、发布时间（如有）、服务端查询时间及状态，作为不可信资料传给模型。查询时间不是网页更新时间，网页结果不是地图距离/实时营业核实。外部文本不能改变提示规则或进入正式记忆写入接口。
- 不创建新记忆状态、任务或数据迁移，不新增定位权限，不修改iOS音频及收尾流程。真实供应商返回结构、原生查询证据/来源、超时继续对话仍须单独验证；受控测试只能证明代码合同。

地点追问允许在本地结合紧接的上一条用户公共问题解释“杭州”等城市回复，不能用助手自说内容或私人记忆替代用户地点。对搜索供应商仍只发送拆出的公开关键词。6秒上限属于文字HTTP查询；当前原生模型内部搜索的耗时及错误回调合同尚未实测，不能把文字超时保证套用于Live。
