# 关系审核降级误报内容遗漏：分析与修复设计

日期：2026-10-05。关联登记：DJ-LIVE-CLOSURE-REVIEW-20261001。用户授权按本方案开发。证据目录：`outputs/2026-10-05-relation-completeness-repair/run-01/`。

## 1. 已证事实与未决问题

上一场自然十分钟测试保存44条正文，发布2主题、28个提取事实，publishedMembers集合与全部atom完全一致；missingRanges、omittedAtomIds、failedTurnIndices均为空。唯一blockedThemes条目是relationResolutionFailed / relationValidate.schemaInvalid，覆盖全部28个atom；因此completeness变为partial。用户实际看见“完成，但附带少量内容未整理”。证据见[上一场报告](../2026-10-05-同场重复事实误判时间变化/部署与真机验证.md)。

代码已证：RecoveryThemeAssembler将关系失败拼入blocked，再执行完整上下文安全复核；即使复核放行全部主题，原关系失败仍在blocked中，直接导致partial。这混淆了关系识别质量和内容覆盖。

批次关系解析将缺行、错误索引、非法关系、无效补充记忆等错误统一转换为schemaInvalid，丢失安全可记录的具体原因。现有原场归档未保留失败模型响应，不能认定具体字段、超时或容量是原场首因。提示词仅有空decisions示例，未明确禁止非supplement携带resolvedMemory（解析器实际拒绝），supplement所需facets及证据字段约束也不完整。这是可重现的合同说明缺口，不等同已还原历史响应。

## 2. 目标与影响范围

仅修改后端：DeepSeek批次关系请求/解析；Worker安全诊断；恢复主题装配的覆盖判定。新增专项测试和隔离PG验证。无数据库迁移，无iOS协议破坏，无新增用户状态。

不改正文采集、保存队列、结束水位、自动告别、麦克风、音频、公共查询、正式记忆确认权限、同场精确重复规则。不得修改生产/历史记录、自动重试旧场、部署、手机或push。真实模型仅允许本轮最多8次全新合成请求，使用既有配置，不创建业务任务，不传输私人正文。

风险：将危险的更正/撤回判断失败伪装完整。控制方式是继续强制全上下文安全复核；只有实际可发布主题覆盖完整且原文无缺口，才可标内容完成。不能只删除提示，也不能把关系未决记为关系通过。

## 3. 实现规则

### A. 关系合同与诊断

- 批次提示明确整数索引、结果完整、每事实最多一个目标、无关时空列表；只有supplement可带resolvedMemory，其他关系必须省略而非null。为非空决策提供形状示例，不指定测试答案。
- supplement继续走现有严格记忆解析、用户证据校验及后续独立支持复核；明确memoryKind/主字段/sourceTurnIndices/facets及公开证据字段。不信任模型复制的内部_atomIds/_sourceEvidenceRanges。
- 将批次解析错误细分为稳定、无正文的原因码；不记录原文/密钥或异常原字符串。附带响应摘要哈希、finish_reason/usage等安全观测，并写入既有attempt诊断。
- 不将非法输出强行改成合法，无新无限重试、不扩大页大小/预算。非法响应不得标completed；恢复复用必须仍验证合同/hash。

### B. 内容覆盖与关系质量分离

- 关系消解失败单列manifest.relationDiagnostics，保留failureCode、受影响atom及安全复核状态；不再冒充blockedThemes。
- 关系失败仍触发guard_partial_themes，输入仍是全部收到的用户原文。未通过安全复核的主题继续移除，真实遗漏进入omittedAtomIds和blockedThemes。
- failedTurnIndices、omittedAtomIds、真实blockedThemes以及源metadata的不完整状态仍决定partial；关系诊断本身不代表丢失正文或事实。
- 不修改已有快照和旧manifest；发布哈希包含新诊断字段，幂等/事务/权限保持现状。旧现场仍保留原结论。

## 4. 验收断言

1. 同断言修前红/修后绿：关系失败→完整安全复核→所有事实保留时不误报partial；仍保留具体诊断。安全复核阻断、更正/撤回、丢正文、提取失败、源结束位置未知继续partial或失败，不能伪报完成。
2. 请求/解析：合法独立、重复、补充、更正、撤回通过；缺行/重复索引/布尔或浮点计数/坏目标/非法enum/非补充带resolvedMemory/缺facets/无效证据拒绝并给出具体无值原因。非法缓存不使用、最多原预算、无效输出不completed。
3. 使用受控HTTP经过真实adapter/Worker；新增真实DeepSeek合成请求最多8次，保留每个原始合成请求响应和失败，不反复重试到通过。Provider单独记状态，不代替真机。
4. 隔离PG默认API/Worker：独立短A→逻辑十分钟→短B；逐轮正文、候选集合与证据、确认→正式记忆→重建读取。追加注入关系格式失败但安全放行的真实发布场景及安全拒绝反例，核对返回isPartial与落库manifest一致，幂等/并发/回滚保护不退化。沿用当前十分钟产品策略，不新增65分钟测试。
5. iOS同版保存与状态回归、开麦/音频/告别重点及受控生产Manager；检查xcresult真实pass/fail/skip，不用构建成功代替测试。不开手机、不以手机缺席阻塞本地交付。
