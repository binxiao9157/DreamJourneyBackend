# S5 跨来源同文补证误判：分析与修复设计

2026-10-11。状态：设计冻结，修前反例已取证，实施与验收进行中。

## 1. 事实及根因

真实 iPhone 输入“我把鱼食装在绿色的密封罐里。”后，独立来源生成候选。已有正式事实与候选可见正文完全相同；实际 payload 差异仅为 qualifiers.polarity positive/unknown、provenance.evidenceRefs 和 sourceTurnIndices。确认预览返回 dispute / sameAssertionCannotSafelyMerge，自动确认正确阻止，无正式写入。该结果不能称为合法 noChange 或补证成功。

根因是关系判定的确定性边界缺失：同来源规则允许这种提取标签差异，跨来源的严格形状比较则同时包含 polarity 和来源轮次。现有弱化复述规则没有覆盖该体验类型，最终落入争议。不能泛化为所有 unknown 都等价，也不改目标选择规则。

证据目录：`outputs/2026-10-11-memory-dialogue-s5/run-04-closure/`；精确反例 `add-evidence-reproduction-fixture.json`，差异 `add-evidence-content-diff.json`，真实预览 `device-evidence-confirm/relation-preview.json`。

## 2. 影响范围及边界

仅修改后端 `app/domain/owner_truth/memory_changeset.py` 的关系判定，增加对应单元及隔离 PG 服务验收。三入口共享确认服务均可能受影响，故验证其共同确认边界并补最终同版短场→自然十分钟。

不修改检索、来源采集、批处理、候选发布、确认写入事务、目标选择、音频、iOS、正文生成或现有同来源规则。不新增模型调用。已确认事实不改写；仅按原 ADD_EVIDENCE 协议新增证据和版本。现有 MIC04 例外及正文阅读基准保持。

## 3. 实现契约

增加独立的严格比较辅助函数：双方 statement 非空且原文相等；polarity 必须恰为 positive/unknown；除来源级 sourceTurnIndices 与 provenance.evidenceRefs 外，全部内容必须一致。比较时仅统一上述 polarity，不忽略主体、时间、场景、出处模式、贡献者或 semantic 内容。negative、不相同正文、任何其他字段变化均不能进入捷径。

放在既有主体、目标选择、时间及极性冲突检查之后。符合条件且有新证据则 ADD_EVIDENCE，无新证据则 DUPLICATE。使用既有写入实现保留已审核事实和其他正式版本，不给未知标签新增确认权威。

## 4. 分步验收

1. 使用现场 payload 在隔离源码副本复现同断言修前红，修后绿。双方向 positive/unknown 覆盖；明确否定、主体/时间/场景/语义变化、来源贡献者变化均不得走捷径；不修改同来源规则。
2. 隔离 PostgreSQL 通过真实 preview/confirm 服务：相同正式 ID，仅版本/证据递增，旧业务正文逐字段不变，两来源引用完整，重放不新增版本，新连接冷读一致。明确这不是供应商提取 E2E。
3. 后端受影响确认、S3/S4/S5、Live 保护回归。本次 iOS 源码未变，复用已证明依赖不变的既有用例；测试工具仍用 stage-03 冻结版本。
4. 部署本次唯一应用文件变化；核对 API/Worker 运行镜像和文件哈希。真实 iPhone 对原待确认候选续确认：精确 source hash、candidate ID、target ID/version 和 addEvidence 白名单，不放宽争议确认。
5. 同部署最终独立短场→自然十分钟；保留源正文、候选、确认/冷读、音频及收尾状态证据。转写差异不中断场次，正式确认前按用户批准范围处理。

## 5. 回退与结论纪律

保留部署前镜像和源文件；异常先保存现场，不重试未知确认结果。事务结果只读核实后决定。修前短场及失败补证保留，不冒充修后通过。只有补证、最终组合及 S5 清单全部满足才关闭 S5。正文效果优化留待后续。
