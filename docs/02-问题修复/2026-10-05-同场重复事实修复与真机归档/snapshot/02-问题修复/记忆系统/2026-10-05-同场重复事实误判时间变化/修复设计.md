# 同场重复事实误判时间变化：修复设计

日期：2026-10-05。依据：[现场分析](问题分析与剩余主题核对.md)、[后续确认记录](本场继续确认记录.md)。用户已授权按方案开发。本文件记录决策和验收边界，不代替验证结果。

## 1. 问题与目标

实际合成十分钟场中，“提前十分钟到教室复习”原文及提取 statement 相同，前后候选却分别带 current / historical，以及非空 / 空地点、场景和极性。确认比较器只要 scope 不同，就生成 temporalChange。“学习陶艺/学习陶艺时”“练习陶艺/练习陶艺时”也触发同类操作。前者目标是同组前项拟新增的虚拟记忆，后者还包括同场已经正式确认的记忆，不应统称旧历史污染。

直接根因已证实为确定性比较规则过宽。提取字段为什么发生漂移仍未证实；本次不声称查清全部模型质量问题。候选生成和主题发布已经发生，本缺陷位于待确认→正式记忆的关系预览与提交，不是此前正文丢失或发布失败的同一断点。

目标：相同来源版本、相同明确事实的非语义字段退化或极窄措辞差异，不产生虚假的时间变化；只补充证据，保持已确认内容。真实变化、更正、相反极性、不同主体继续保持原有可审核操作。

## 2. 影响范围与边界

业务修改限后端 `app/domain/owner_truth/memory_changeset.py`，共用的单条、分组预览、确认重新计算、虚拟记忆和激活均自然复用。新增回归文件及脱敏合成现场夹具。无需数据库迁移、接口或 iOS 协议变更。

不改：正文采集、保存队列、结束水位、草稿整理、模型提示词/调用预算、主题发布、原子组确认、权限/CAS、回响三状态、开麦、音频、告别、联网查询。不会自动确认现有18条待确认，不修改历史数据，不增加模型调用，不扩大自动化工具的纯 add 白名单。本次仅本地开发，不部署、连接手机或 push。

风险：把实质变化误当重复，会丢失变化表达。因此不使用模糊语义相似或通用“空值等于已有值”；新分支有明确限制，且仅允许 duplicate / addEvidence，不能覆盖正式事实。比较器没有读取原文的能力，不能声称它验证了原文逐字相同；它验证的是已入库候选的明确文本、来源身份与字段约束。原文支持仍由既有候选证据链负责，现场夹具另做原文精确核对。

## 3. 判定规则

保留显式更正、个人问题及主体/记忆类型/断言键比较顺序。在既有 scope 差异→temporalChange 之前增加“同来源精确重复”分支，全部满足才进入：

1. 候选与目标已经命中既有 assertion key，memory kind、claim subject 均符合原规则；不得跨 vault/owner。
2. 候选全部证据属于同一有效 Source ID + version，且目标含同一来源版本；证据有合法非空 span。不能用缺失引用、其他来源或其他版本触发。
3. 非空 statement 相同，仅规范空白。主体、谓词、对象、event/summary、其他业务内容仍须相同。新增 substantive 字段不能被忽略。
4. 双方没有显式 validTime；有年份/日期/有效时间表达或不明时间表达就交回原规则。两边已知且相反的 polarity 不进入重复。
5. 地点只能相同或候选缺失；不同非空地点或实体 ID 不合并。场景只允许相同、候选缺失，或末尾单个“时”的差别；不做任意包含或同义词猜测。
6. currentApplicability 的注释漂移仅在上述强约束内不单独作为时间变化证据。其他 qualifier 不允许新实质值替换已有值。
7. provenance、sourceTurnIndices、semantic、facets、dimensions 是来源/派生索引，不因它们不同覆盖旧内容；新增证据仍完整保存。保留原记忆的这些字段，不将其顺便重新归纳。

满足后：有新 source span → addEvidence；没有新 span → duplicate。调用现有激活流程，addEvidence 保留 memory ID 与原业务内容，仅生成新版本并合并 provenance / evidenceRefs；duplicate 不新增版本。使用独立 reason 便于审计。未满足条件全部回到既有分类，不扩大合并范围。

不修改 comparable 的排序或跨类别召回，不解决“用户/我”、不同 predicate、跨主题归纳重复。多目标歧义不通过本次做全局消歧。

## 4. 并发、回放与既有提案

预览与确认使用同一比较器。保留候选版本、memory revision、proposal hash、主题成员集合和依赖校验。旧提案在规则改变后必须重新预览；旧 hash 不得绕过确认。保留组内虚拟版本更新、原子事务和重放幂等机制。不会把旧 temporalChange 提案直接改写成新操作，不回填生产回执。

## 5. 验收矩阵

- R1：保留真实供应商生成的合成场字段及来源 span，三类误判用同一断言修前失败、修后 addEvidence；已有 span 重放 duplicate。
- R2：组内首项 add、后项 addEvidence；只形成一个 active memory，保留两处证据。另测已有正式记忆的补证及独立回读。
- R3：明确年份/时间变化、相反极性、实际场景/地点差异、实体 ID 冲突、不同来源/版本、缺失或坏 span、不同正文、新业务字段、不同主体、显式更正均不得被新规则吞掉。
- R4：现有 ChangeSet 单条、激活、分组、审核、质量保护回归；旧预览 hash 与并发/回放保护维持。
- R5：隔离 PostgreSQL 实际组确认、重放、重开连接读取，精确比对正式内容和证据身份；测试数据只在隔离库。
- R6：同版默认 API / Worker / 隔离 PG 依次短A→逻辑十分钟→短B，正文、候选、正式确认、投影重建读取完整。逻辑时间不等同物理十分钟。
- R7：iOS 开麦、音频、告别及保存回归；检查 xcresult 实際 pass/fail/skip，不以构建退出码冒充测试通过。iOS 未改，仍执行回归，真实硬件听感不由模拟器证明。

受控模型用于保存链故障定位；本缺陷测试额外使用已有真实 Provider 输出夹具，不让假模型统一返回理想格式。此规则阶段没有新模型交互，真实 Provider 新调用仍 NOT_RUN，不据此重写原真机 FAIL。

## 6. 交付、发布与回退

归档设计、修前红/修后绿、隔离 PG、保存链、iOS 结果、源码指纹和未覆盖项。只有本矩阵本地条件满足才给本问题 LOCAL_PASS。部署/真机/历史重处理/Git推送分开记录。

后续用户主动部署后，用新内容短场先通过，再十分钟，检查准确重复得到补证、真实更正仍可见；人工确认/自动确认工具按原授权边界执行。旧18条候选须重新预览后逐组检查，不自动批量接收。若分类回归，回退本比较器改动即可；无需迁移回滚，不回滚已审记忆，受影响记录另行核对。
