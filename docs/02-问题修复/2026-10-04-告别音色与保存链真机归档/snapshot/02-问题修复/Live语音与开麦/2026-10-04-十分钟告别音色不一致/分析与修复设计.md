# 十分钟告别沿用当前 Live 音色：分析与修复设计

日期：2026-10-04。问题编号：DJ-LIVE-FAREWELL-VOICE-20261004。
用户授权：归档修复方案并开发。部署、安装、真机及 GitHub 推送另行执行。

## 1. 已证根因与目标

EchoViewController 的十分钟收尾调用 EchoLiveFarewellSpeaker，内部使用 AVSpeechSynthesizer 与 zh-CN 系统声音。正常 Live 使用当前 SpeechEngine 会话的火山音色，两者不一致；不是用户听感误判，也不是火山擅自换音色。旧方案曾有意选用本地固定告别，本次用户明确要求取代该选择。

保留十分钟后等待当前轮结束的规则、固定友善告别文案、20 秒告别总预算、异常兜底与原有 stopVoiceCapture 保存链。唯一产品变化：告别音频由当前火山会话播放，继承本场实际配置的 speaker（含可用的自定义音色），不使用系统声音或另一默认音色。

## 2. 方案与供应商边界

当前 SDK 已有 SayHello 指令及在会话内提交指定文本的实际路径。采用当前已激活引擎发送 JSON 编码的 content，不新建会话、不发送虚构用户提问、不修改回答权威或全局工作模式，不重新取得 ticket/登录。

官方资料：[端到端 SDK 接口](https://docs.volcengine.com/docs/DoubaoVoice/End-to-endAndroidSDKinterfacedocumentation?lang=zh)。该页同时列出 iOS 版本及共享事件协议，描述 SayHello/content 及 chat_tts_text 类型；不能把网页描述视作本机 SDK/真实服务验收。当前工程 SDK 与原生回调路径仍需分别核对；真实 Provider 与真机听感单列状态。

### 2.1 Controller

- 等本轮业务回复播放完成后暂停 recorder，避免把告别作为用户输入。
- 向当前绑定的 Manager 提交一次 farewell；保留当前 productSessionID、accountLease、limitIdentity 三重完成保护。
- 接受实际播放完成才走正常结束；提交拒绝、供应商错误或现有 20 秒预算到期均走原有保存收尾，不转用系统语音、不无限重试。
- 光球继续使用现有 SDK 播放 PCM 音量；不增加第二个播放器。

### 2.2 Manager 的专用告别生命周期

- 仅接受当前绑定、有效账号、userControlledLive、recorder 已暂停、播放器启用且没有其他播放中的会话。
- 保留会话音色参数；不初始化/重建引擎，不更改 speaker。
- 请求先登记，再发指令；只绑定新出现的 chat_tts_text reply_id，排除本场已见回复。回调仍受现有引擎代际、操作和账号验证。
- 告别 TTS/Chat 不进入普通回答、轮次计数和记忆事实管线。对原生并发入口只隔离告别阶段 assistant 回调，保留已在途 owner 尾段及原关闭封存机制。
- TTS 合成结束不代表用户听完。复用现有播放完成验证：匹配的合成结束加播放器终态；SDK 丢失播放器终态时，用解码/实际播放 PCM 的样本数、内容哈希及真实静音尾段证明排空。
- 故障只完成当前请求一次；取消/关闭/账号或引擎替换清除旧请求，迟到事件不得结束新场。

## 3. 影响范围及保护

| 范围 | 修改/影响 | 验证 |
|---|---|---|
| EchoViewController 十分钟告别 | 删除系统朗读，调用专用 Manager 方法 | 等本轮、一次提交、旧完成隔离、超时/失败仍封存 |
| DialogEngineManager | 当前 SDK 内告别状态/提交/回调分流 | 同引擎参数不变、真实 Manager 受控 SDK、PCM 完成、错误和迟到事件 |
| 原生 transcript 入口 | 告别阶段 assistant 不登记 | 不生成假事实，不漏既有 owner 尾段 |
| 普通开麦与正常音频 | 共用 Manager，存在回归风险 | 开麦拒绝/截止、播放/打断/PCM、光球采样 |
| 短长场记忆保存 | 共用停止入口，禁止改写业务策略 | 短场门禁先过；逻辑十分钟自然结束、持久化 close intent/尾段，候选及正式回读沿既有测试 |
| 后端、模型整理合同、DB、认证 | 不改 | 复核源码指纹；复用未变后端证据并标明，不宣称本次真机通过 |

不新增功能、音色选择器或系统 TTS 兜底；不扩大预算、不改登入/正式记忆权限、不修改主题/关系审核。

## 4. 测试与验收

**2026-10-04用户补充：每场完成取证后、下一场开始前，删除当前测试账号/档案的旧测试正式记忆及待确认候选，核实有效列表、检索和注入不含旧目标。短场产生的记忆在十分钟场前同样清理。** 顺序为清理核验→短场完整验收→归档→清理核验→同版十分钟；清理不通过不得开下一场。[完整执行和验收规则](../../测试与验收/2026-10-04-真机测试场次间旧记忆清理/测试方案补充.md)。保留原始证据和原门禁，不把文档要求当作已执行删除。

1. 修前业务红：十分钟触发后实际 Controller→生产 Manager 路径没有向当前 SDK 发 SayHello；使用同断言复跑修后绿，不仅检查字符串存在。
2. 正例：同一 engine/speaker 参数不变，暂停后只提交一次；合成结束不提前关闭；实际 PCM 排空或正确 player finish 后封存；告别不会增加业务正文/候选。
3. 反例：旧 reply/旧 generation/不同 binding、重复终态、空音频、错误或缺失结束、directive 拒绝、暂停失败、手动关闭、超时不得误报已播完；旧完成不能关闭新场。失败继续核对 close intent 与尾段，不一报错就停止验收。
4. 最终源码运行相关 iOS 回归及独立生产 Manager 受控 SDK 测试，检查 xcresult 实际测试数与失败；通用 iOS 无签名构建。短场、十分钟收尾、音频与开麦是明确必验项。
5. 真实 Provider 只能证明协议/返回音频；真机才证明 SDK 播放及听感一致。本轮如未调用/未安装，明确 NOT_RUN。后续物理十分钟前先同版短场，检查音色、关麦、候选可见、正式确认与回读，不能以单测数替代。
