# 发布后 Run 终态未收敛：分析与修复设计

2026-10-04。范围：一个后台生命周期问题，不修改UI三状态、模型提示、事实归纳、候选审核或正式记忆规则。

## 已知证据

最新真实短场及十分钟均发布、确认和冷读成功，服务器快照published但run仍organizing。最近长场107个模型请求、116计划单元，仅是观测快照，不足以断言无限调用或资源泄漏。

代码定位：candidate worker的recovery assembly分支更新live_recovery_snapshots和主题；旧路径mark_published被assembly is None限制，不会在新恢复路径执行。新路径缺少run完成写入。默认模型调度仍受job及工作单元状态控制：已完成job不会仅因run organizing再次领取，atom调度只领取planned/running的atomExtraction。故已确认状态维护缺口，未证明额外付费调用。

## 修复设计

1. 将恢复快照发布持久化收口到Recovery Repository。在现有候选、主题、消费回执、job完成的同一事务里，锁定恢复会话，再更新对应快照及run。发布失败或事务回滚不留下伪published run。
2. 校验账号/vault/authority、会话generation、snapshot/source绑定，保持旧legacy final Source分支独立。仅当前最新快照已published/noChange、坐标frozen且无未快照补缺、无待提取atom单元时，将该恢复run标published；旧修订完成不能结束正在处理的新修订。
3. 正常无候选/noChange同样结束；失败run不被复活，不清空历史失败证据，不强行将失败单元改为成功。
4. 合法新正文或迟到结束位置使pendingSnapshot由坐标转换产生时，仅重新激活该恢复run（published→organizing），继续原预算/截止/计数。重复回执、只读状态和周期扫描不重新激活。不扩大补缺窗口或重发业务。
5. 周期扫描遇到已published run时跳过草稿规划，不制造plannerRunTerminal伪故障；已有未完成/失败边界保持。空正文快照noChange也走同一终态收口。
6. 不批量修改历史run；本轮不部署、不连接手机、不新增真实模型调用。真实Provider合同及请求体不变，本地用受控模型实际HTTP+隔离PG验证生命周期。

## 验收

- 同断言修前红/修后绿：真实默认Worker发布后snapshot与run终态一致；候选/正式记忆链不变。
- 隔离PG验证：partial发布及迟到补缺第二修订、重复ACK、迟到结束位置、旧修订完成不能结束新修订、失败run保护、跨账号/Source拒绝、事务回滚、无正文noChange。
- 默认Worker再扫描不新增模型调用/候选；记录请求数与预算不重置。并发迟到补缺/发布按恢复会话行锁串行。
- 短A→逻辑十分钟→短B顺序保存发布及正式回读；本地逻辑场不冒充物理真机。
- 相关回归覆盖现有关系分页、发布降级、恢复和短长保存。保留此前合法降级和UI显示完成行为。

## 交付边界
