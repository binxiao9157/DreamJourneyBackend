## 3. A：关系结果完整验证与完成状态修复

### 3.1 一个验证入口覆盖新响应和缓存响应

主修改点：[候选Worker](/Users/gaominge/Documents/Codex/Video/DreamJourneyBackend/app/async_effects/owner_truth_candidate_extraction_worker.py)中的 `_relation_batch_page`、`_validate_relation_batch_results`、`_resolve_cross_batch_relations_batched`。

将完整关系合同校验置于记录unit结果之前；缓存复用也调用同一个验证入口。验证器必须拿到intra_batch、原输入页及身份映射，不能只拿数组长度。

必验：

1. 返回结构、必需字段、枚举、整数类型（排除bool）、唯一incoming编号、全页覆盖及结果条数。
2. 批内目标严格满足 `0 <= existingIndex < incomingIndex`；第一项没有前项时返回空decisions。自引用、向后引用拒绝。
3. 跨批指向当前冻结existing页中的真实目标；不能把前一页局部索引当下一页索引。原输入hash、页身份及证据归属一致。
4. 重复、补充、纠正、撤回关系仍执行既有来源支持复核。结构正确不代表语义正确；同主题不同事实不得直接删掉。
5. 多目标含混、未知枚举、无证据关系均明确失败，不静默改为空结果，也不把非法自引用强行改成合法重复。

传输成功、响应解析成功、业务校验通过、持久任务完成分别记录。**HTTP200不能直接使业务unit进入completed。**模型尝试的费用/调用事实仍如实记账，不能因回答被拒绝而退还预算。

### 3.2 新响应的持久状态与预算

新响应先验证，再在现有事务/租约约束下完成结果提交。非法响应保留responseHash、验证版本、stage/reason及输入hash，进入现有可恢复失败或终止失败分支，不写入可复用的completed覆盖。

- 模型已返回但关系非法：若原单元仍有既有合同恢复名额，可按已有策略进行一次修正请求；没有名额即终止本单元或走已有可靠部分复核路径。
- 本轮不得提高 `maximum_unit_extra_requests`、整场请求数、token或时间预算。实施时读取该run持久预算，不只读当前默认配置。
- 不能换unit/run/job/source身份获取新预算；换快照也不能让相同逻辑工作反复重获名额。
- 修正请求应明确前次违反的合同和允许目标范围，且仍受请求大小/输出限额约束；不携带无关对话。
- 崩溃、进程重启、并发Worker、提交结果未知、权限epoch变化均按现有租约/事务保护，不允许两个执行者同时完成不同结果。

### 3.3 兼容已经存下来的非法completed

读取completed时重新验证完整合同，校验失败必须停止复用。采用**保留原完成记录、附加输出拒用诊断**的方式，不抹除原响应证据，不直接把旧completed覆写成新的合法结果。

本次发布不自动扫描或重跑历史失败场。对已经被合法调度的活动任务，可将非法缓存转换为明确的关系失败，保留原始facts，并进入已有安全复核兜底；不得无限反复读取同一错误结果，也不能无证据发布。

若未来需要重新调用模型修复历史缓存，单列运维方案：范围清单、原run预算/权限验证、审计、幂等与回滚，取得历史处理授权后执行。不能夹带在新版本启动时执行。

## 7. E：错误后继续验证收尾兜底（本次新增）

### 7.1 三条线路分开

测试记录分别维护：

1. **对话过程**：Live、文字、音频、逐轮保存及实时性；首错出现后FAIL保持，不因后来补齐而清除。
2. **异常收尾**：停止意图/服务器失联收束、已有正文补传、尾批整理、可靠主题发布；独立PASS/PARTIAL/FAIL/NOT_RUN。
3. **记忆确认**：读取本场待确认→明确确认→正式记忆→进程重建回查；独立结果。合法纯问题无候选为N/A，有可靠事实却无候选则不能N/A。

### 7.2 发生可控错误后的动作

测试工具进入“恢复观察”阶段，停止注入新语音和新用户轮，不新开场，不杀App/结束测试宿主/停止后台服务。冻结首错时间、最后已输入/已接收/已持久/已ACK的位置，保留不完整当前轮的实际状态。

按产品正常错误处理或公开停止入口请求收束，保存停止来源（产品自动停止/测试发起正常停止）。不得直接替产品补写close intent、伪造end/ACK、手工调用候选生成、清任务、重置budget或调用内置测试helper绕过链路。

让产品自身完成已接受事件封存、停止意图、原身份补传、服务器收束/尾批、主题发布。低频只读观察状态；不反复点击“核实”触发新的恢复轮次。避免finally立即结束整个进程；退出清理安排在观察结束和证据保存之后。

这是小范围测试生命周期修改，不重构工具、不修静音、不放宽0.5秒送帧失败阈值。

### 7.3 必须分别验证的异常路径

| 异常 | 观察方式 | 不能被替代的断言 |
|---|---|---|
| 自动工具送帧错误，但App仍运行 | 停新增输入，通过正常停止入口收束 | 记作工具触发错误，不谎称真实SDK自动故障；检查本场已有内容是否自动发布 |
| 产品SDK断连/错误 | 允许生产错误回调驱动停止 | 不额外代写end；停止动作和恢复归属于同场 |
| 本地已落盘、网络或ACK暂时失败 | 恢复网络后让现有队列自行补传 | 原身份且服务端去重，无重复正文/候选/正式记忆 |
| 没有end通知/进程突然终止 | 此专项故意不发停止请求；保留服务器与观察器 | 默认扫描器在原期限内冻结已收到范围并处理尾批；不能由手动end遮盖 |
| 模型错误或其中一页失败 | Live收束后观察原Worker执行 | 合法重试有界；可靠独立主题可发布；受影响纠正不能错误放行 |

异常兜底测试可以主动注入上述故障；正常长场不为凑异常断言而人为失败。若正常场真实发生错误，可收集兜底证据，但该正常物理场仍FAIL，后续长场暂停。

### 7.4 有界观察与退出

测试启动前从实际配置和run持久预算记录：断连/心跳等待、补缺deadline、扫描/轮询间隔、单请求deadline、单元重试名额、整理 inactivity/absolute deadline，并生成一次性的 `observationDeadline`。不能把文档建议60/90秒当成部署实测值。

观察上界按仍需依次经过的恢复等待、补缺和可用模型处理窗口计算，扣除已消耗时间，并加一次状态读取周期；同时设定测试墙钟上限。不得因只读轮询或进度文案刷新无限延期，不改变产品预算以适配观察器。

结束条件：

- 已收束且本场候选/明确的部分结果稳定可读，待确认阶段结束；有授权的本场合成新增记录再进入确认/正式回查。
- 产品已到明确终止失败且无待执行合法恢复，保存终态后结束观察。
- 墙钟上限先到，记 `OBSERVATION_TIMEOUT`，列出仍在进行的任务及缺少的断言；不是自动宣称产品永久失败，也不是PASS。
- 持续磁盘不可写、账号归属异常、用户要求停止、设备过热或无法安全保持时，立即停止相关活动并保留证据；不为了观察继续制造数据。

如产品在观察结束后仍可后台执行，保留恢复坐标并说明；测试退出不清数据。物理设备被终止进程的专项在本地验证之后、经用户发起真机阶段执行，不误杀日常App。

### 7.5 输出与证据

生成单场时间线：首错 → 最后接收位置 → stop intent/失联deadline → 手机durable → 服务器ACK/缺口 → snapshot/Source → 尾批 → 模型状态 → 发布manifest → 候选读取 → 正式确认/冷回查。

逐项比对messageId、role、正文hash、Source版本、事实及证据集合、主题版本与正式记录映射；不要用“服务器数=手机数”代替身份一致。少量遗漏列出范围和原因；不能把内部atom当候选、pendingReview当列表已可见。

示例结论：`CONVERSATION_FAIL / RECOVERY_PASS / MEMORY_CONFIRM_PASS / DEVICE_20M_FAIL`。即使已保存内容成功进入正式记忆，不足20分钟的测试也不升级为20分钟成功。
