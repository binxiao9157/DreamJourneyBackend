## 4. 最小实现方案

### 4.1 统一发现结果，保留可信时间

把普通恢复 plan 和 blocked record 都投影为可展示条目，带账号作用域、产品场次身份、可信创建时间及来源、状态、观察版本、可用只读坐标。blocked 不等于可以构造一个有权限发请求的 coordinator。

可使用已有 outbox envelope、follow-up 和 checkpoint 的创建时间；必要时只增加其只读 snapshot 投影。不要用本次扫描时间、GET 返回时间、会被恢复操作修改的 updatedAt 或 ID 字典序判定“最近一次对话”。时间未知就明确未知，不能编造顺序。

### 4.2 稳定选择场次

当前显式交互的场次或有效用户选择优先。真正冷启动没有旧 Controller/闭包/人工传入 productSessionID 时，按可信场次创建时间选最近条目；最新 blocked 同样具有展示资格。历史场回调只更新该场缓存，不抢占已选场。

不能采用“任何 blocked 永远压过成功”的简单优先级：旧失败、新成功的反向场景应正确显示最新成功。时间或身份不足时显示可核实的不确定状态，不能默认用旧成功填空。

### 4.3 一个展示快照控制文案和动作

引入按 scope/workflow 保存的状态缓存与稳定 selector。capture/recovery 的回调均先更新自己的记录，由唯一入口取所选场完整快照，一次性更新状态、文案、核实按钮及按钮目标。

保留请求层已有 generation/账号/plan 校验；另外按页面可见代次隔离 UI 提交。离页、后台、账号变化后的迟到回调不能重建旧展示权。相同场较旧 observation 不覆盖较新结果。

新文字入口独立于历史核实，继续服从真实账号/FeatureGate/当前交互权限。没有可靠查询坐标的 blocked 条目可以展示原因，但不能借旧场 coordinator 代查，不能通过 POST 修正 UI，也不能暗中重开麦克风。

### 4.4 只读恢复保持有界

将同一可见/激活周期的导航、前台、active、readiness、policy 完成通知归并成一个读取意图，保留既有 deadline、GET 次数、取消与单飞。非选中历史任务结果只能入其缓存，不能反复因通知为所有任务重开轮询。

本项不改变 start/append/end/ack/admit、unknown-write、canonical 封存或 B7 语义；不删除、重放、迁移或“修好”现有历史任务。
