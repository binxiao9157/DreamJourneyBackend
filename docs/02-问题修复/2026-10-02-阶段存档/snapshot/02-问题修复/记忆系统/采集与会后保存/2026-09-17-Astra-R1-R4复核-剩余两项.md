## 2. 剩余 A：非空场 closeIntent 后，冻结但尚未登记的新成员仍会被拒绝

证据链：

1. [Echo:1303](/Users/gaominge/Documents/Codex/Video/DreamJourney_dev/DreamJourney/Sources/Modules/Echo/EchoViewController.swift:1303) 的 `submitFrozen` 把首次 `registerCanonicalMember` 和正文一起放进延迟 delivery；router freeze 完成时，Store 尚不一定知道该成员。
2. [Echo:1632](/Users/gaominge/Documents/Codex/Video/DreamJourney_dev/DreamJourney/Sources/Modules/Echo/EchoViewController.swift:1632) 的 `finish` 在已有内容时进入关闭；[1834](/Users/gaominge/Documents/Codex/Video/DreamJourney_dev/DreamJourney/Sources/Modules/Echo/EchoViewController.swift:1834) 会将 closeIntent 排进持久化队列。
3. [Store:16259](/Users/gaominge/Documents/Codex/Video/DreamJourney_dev/DreamJourney/Sources/Domain/OwnerTruth/OwnerTruthContracts.swift:16259) 在 closeIntent 已存在时拒绝新成员。冻结在前、首次 Store 登记在后的合法成员仍会发生冲突，不能因 sink 已绑定就认为排空闭合。
4. [现有 replacement 测试:1213](/Users/gaominge/Documents/Codex/Video/DreamJourney_dev/DreamJourneyTests/OwnerTruthContractsTests.swift:1213) 从空的 A 场开始，把全部登记都延迟。停止时 A 走 `.empty` 分支，没有写 closeIntent，所以避开了正常非空场的冲突。

必须新增的确定性反例：

- A 场先完成至少一轮实际落盘，确认 owner/已登记内容非零。
- 下一问题的 identifier-only 和 final 已在 router freeze，但暂停首次成员交接。
- 停止 A，等待已有关闭意图实际落盘；可同时建立 B 场验证隔离。
- 恢复 A 的交接。断言停止前已接受成员和正文保存在 A、B 零旧材料；关闭 N 包含这些合法 delivery，不能提前 end，也不能以 conflict/unavailable/empty 丢掉它们。
- 再验证停止后的真正新成员仍拒绝，账号失效仍零跨账号落盘。

修复方向：在关闭边界前完成成员资格登记，或使用可信的冻结成员清单/交接计数与持久 barrier，使关闭覆盖 router 已接受、尚未交接的材料。`finish` 的空场判定和 N/end 决策必须包含这批待交接材料。不得简单删除 Store 的 closeIntent 后拒绝新 ID 规则，也不得允许任意标为 frozen 的旧事件绕过边界；资格必须绑定原 operation/epoch、场次和账号作用域。

如果采用延迟写入 closeIntent 的实现，测试应断言已接受成员登记完成之前绝不写入不包含它们的关闭边界；若采用先写关闭清单的实现，则应验证该清单明确包含待交接成员。两种实现都必须消除上述丢失窗口，不能仅靠调整测试调度回避它。

## 3. 剩余 B：逻辑时钟尚未驱动真实 FeatureGate 的过期判断

这次 R4 的真实组合链、断网恢复和最终关闭成立；不再归类为“仅 Spy 测试”。剩余问题限定为时间一致性。

- [测试:2868](/Users/gaominge/Documents/Codex/Video/DreamJourney_dev/DreamJourneyTests/OwnerTruthContractsTests.swift:2868) 只把 fakeNow 注入 `liveAuthorityNow`。
- [FeatureGateService 构造:429](/Users/gaominge/Documents/Codex/Video/DreamJourney_dev/DreamJourney/Sources/Services/DreamJourneyBackendClient.swift:429) 没有时钟入口；[请求校验:554](/Users/gaominge/Documents/Codex/Video/DreamJourney_dev/DreamJourney/Sources/Services/DreamJourneyBackendClient.swift:554) 调用 evaluator 时未传同一个逻辑时钟。
- [evaluator:373](/Users/gaominge/Documents/Codex/Video/DreamJourney_dev/DreamJourney/Sources/Services/ReleasePolicyStore.swift:373) 默认使用真实 `Date()`。测试的 policy provider 又直接提供 `.useCachedPolicy`，不会随 fakeNow 自行形成缓存过期结果。

因此当前多个刷新由 request authority 的逻辑 expiresAt 检查触发，没有证明同一时刻旧 route/cache 的真实过期决策。这与“同一逻辑时钟下真实 gate 跨 TTL”的原门禁仍有差距。

补验要求：提供窄范围时钟依赖注入，生产默认保持系统时钟；在同一组合中证明 `t0 旧 route允许 → t301 旧 route 因 capturedPolicyExpired 拒绝 → 有界刷新/新策略 → fresh允许 → 实际 transport继续原命令`。gate、缓存时效判断与 request authority 使用一致的测试时间；不要手工把测试 decision 改为 denied 来代替实际 evaluator 判定。保留当前真实 deny 零写、刷新单飞和 unknown 零重放断言。

未补该证据之前，收窄 TTL-L01/L04 对“真实 gate/cache 同时钟过期”的 PASS 描述；无需重写已经通过的整条组合链。
