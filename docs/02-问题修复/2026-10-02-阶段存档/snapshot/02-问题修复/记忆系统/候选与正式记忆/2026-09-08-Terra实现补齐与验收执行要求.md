本文初版保存位置已经用户确认，初版阶段仅更新文档，未执行新的业务测试、部署、迁移、安装、提交或推送；下文的部署要求是交给 Terra 执行 A 时完成的任务，不是部署完成记录。后续 Terra A 本地实现、测试与未关闭阻塞的实际记录见第 18.1 节；该记录同样不表示已经部署、迁移、安装、提交或推送。

## 0. 先读这一页：不得把未完成开发转交给用户测试

用户要求的是完整 B 方案，而不是“若干单测通过的接口骨架”。必须遵守以下规则：

1. **未实现的功能，由 Terra 继续编码；不能改标为“等待用户真机测试”。**
2. **数据库、任务恢复、向量索引、接口集成、模拟器及压力测试，由 Terra 准备环境、编写测试并执行。** 用户不负责操作数据库、核对事务或寻找日志。
3. 用户只承担必要授权、设备解锁/信任/人工操作，以及事实正确性、自然度和交互体验判断。用户反馈“看起来正常”不能替代数据库、权限、恢复和性能验收。
4. 没有依赖、权限或设备时，明确指出具体阻塞、已尝试的办法、所需最小协助和受影响用例；继续执行其余任务。不得笼统把整个项目交回用户。
5. `build-for-testing` 成功不等于测试执行；内存仓储通过不等于 PostgreSQL 通过；注入假向量不等于真实语义检索；请求成功不等于事实被正确写入或模型实际使用。
6. 代码实现、测试通过、可进入设备验证、完整业务验收、部署完成是不同结论，必须分开报告。
7. 原需求未经用户明确批准不得删除、降级或改为后续阶段。需要取舍时提出变更申请，获得决定前仍计入未完成范围。

推荐的工作顺序是：**A 补齐代码 → 本地编译/发布构建 → 自动化及隔离真实依赖验证 → 部署到现有后端服务器 → 部署后接口与运行验证 → 交付并结束任务 → 用户另行接入 iPhone → B 安装配套客户端并配合验证。** 这是工作解耦，不是把完整 B 方案拆成多个产品版本。“执行 A/B”也不是重新选择记忆方案 A/B。

### 0.1 两次独立执行，不等手机、不自动进入下一部分

- **A 部分是默认执行模式。** 用户把本文交给 Terra 开发时，Terra 执行全部开发、本地构建及不依赖 iPhone 的测试，通过后完成现有后端部署及部署后验证，再提交 A 交付结果并结束本轮任务。不要求用户现在接手机、不轮询设备、不挂起任务等待、不自行创建后续自动任务。
- **B 部分必须由用户另行触发。** 用户之后连接 iPhone，再说“按这份文档执行 B 部分”。Terra 先读取 A 的实际部署记录，核对在线版本和环境，按第 15 节执行。B 不再把首次后端部署作为默认待办；真机安装仍按 B 的明确指令和必要授权执行。
- A 中确实只能用 iPhone 测量的供应商背景使用、真实收音/打断和设备级时延，明确移交 B；不能把尚未写完的适配器、审核 UI、数据库事务、检索装配或模拟器测试移交 B。
- A 遇到非设备阻塞，例如真实 PG 无法启动、embedding 未获授权、模拟器缺运行时、发布版本不可取得或后端部署验证失败，应提出最小协助并继续其他工作。若交付时仍未解决，结论只能是 `A_BLOCKED` 或 `A_INCOMPLETE`，不能冒充 `A_COMPLETE`。部署未完成不得转交 B，也不能因为本地通过就宣布 A 完成。
- A 的设备依赖项统一标 `DEVICE=NOT_RUN，预定B验证`，不因手机未连接而把 A 挂起。移交项须有已完成实现、待验证假设、测试步骤、证据采集点和失败后排查方向。

## 2. 不允许改变的产品与架构边界

- B 方案采用现有 PostgreSQL 正式事实体系及同一 PostgreSQL 内的 pgvector 派生检索；不新增独立向量数据库、图数据库或第二份可写正式事实库来绕开问题。

- Live 保持火山原生听说、VAD、打断及续听；不恢复每回合 `ASR → DeepSeek → TTS` 的旧串行链路。
- 文字由 DeepSeek 回答，不自动朗读；可以与 Live 措辞不同，但同一授权范围和版本下不得事实矛盾。
- 逐回合可靠保存，按“用户开启至主动关闭或已定义有效空闲结束”整场整理一次。一个批次可以有多条候选；没有新事实可以明确完成且无新增。

### 3.2 每项必须有两个状态轴

实现状态使用 `NOT_IMPLEMENTED / PARTIAL / IMPLEMENTED`。证据分别使用 `PASS / FAIL / NOT_RUN / BLOCKED`：

| 证据层 | 必须表示什么 |
|---|---|
| CODE | 可定位的实现、生产装配、合同与失败分支；不是只有字段或 Protocol |
| UNIT | 本次版本实际执行的单元/合同测试 |
| DB | 本次版本在独立真实 PostgreSQL 中的事务、索引、故障和恢复结果 |
| MODEL | 获准的真实 DeepSeek/embedding/火山调用及业务断言，不是 fake provider |
| SIM | 模拟器实际执行的测试结果，不是编译产物 |
| DEVICE | 当前配套后端和 iPhone 构建的真实交互结果 |
| OPS | 负载、故障、恢复、观测与费用证据 |
| BUILD | 本次完整源码的 iOS 编译与后端发布制品构建、平台、指纹及运行核验 |
| DEPLOYED | A 中实际部署到核验后的现有后端，API/Worker/迁移版本可核对；单列，不由本地测试推导 |
| POST_DEPLOY | 在实际部署入口完成基础就绪、业务闭环、权限和运行稳定性验证；不能由容器 running 或 /health 200 推导 |

示例：`W05: PARTIAL; UNIT=PASS; DB=NOT_RUN; MODEL=BLOCKED; DEVICE=NOT_RUN`。不能把它压缩成“W05 PASS，剩下请用户测试”。

`BLOCKED` 必须列阻塞对象、所需权限/资源、错误或可复核原因、已尝试的办法、最小协助及不受影响的下一任务。未编写测试是开发工作未完成，不是外部环境阻塞。确实不适用的证据写明依据，不能用 N/A 静默移除原验收项。

### 3.3 环境与权限的硬边界

- 默认先用隔离测试账号、合成个人资料和可销毁测试数据库，不污染用户现有超级账号的正式记忆。
- 现有 `.env`、服务地址或 `DATABASE_URL` 不能直接当测试配置使用。先核验目标主机、数据库、账号权限、存储路径和清理范围，凭据仅通过已有秘密配置注入。
