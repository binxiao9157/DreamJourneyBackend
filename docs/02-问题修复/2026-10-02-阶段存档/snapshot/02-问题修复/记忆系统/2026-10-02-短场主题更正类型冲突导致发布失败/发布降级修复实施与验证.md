# 发布降级修复：实施与验证

2026-10-02；DJ-LIVE-THEME-CORRECTION-20261002。

依据：[收尾严格性核查与十分钟验收重点](收尾严格性核查与十分钟验收重点.md)。用户已授权按讨论修改代码。本轮修改后端，保留原有 dirty 工作区；未改 iOS、测试工具的合格标准或数据库结构，未部署、未操作手机、生产或历史任务，未 commit/push。

## 已实现

1. **把自动关联与新内容发布分开。** 已通过独立事实/主题核验的当前主题，在旧主题关系不确定、多目标、跨页结论不能归并、可选比较容量不足、可选关联预算耗尽时，保留当前已验证标题、摘要、完整成员及证据，作为新待确认发布。不导入旧成员、不更新旧主题、不生成未经批准的正式记忆更正目标。
2. **保留不确定性。** 新发布 manifest 的 `deferredRelations` 记录主题、成员、原因、原主题支持哈希及相关历史版本/提案哈希，整体纳入 manifest 哈希。它表示“暂不自动关联”，不是模型确认了 `none`。本轮未增加 UI 提示字段的展示；用户看到的是当前已验证的新主题。
3. **不为已经不确定的关系反复调用模型。** 模型关系提案明确 `uncertain` 后立即退出可选关联，不再做该提案的后续审核和其他关系页。已发布新主题不依赖这项优化完成。
4. **更正类型不匹配局部拒绝。** 保留 `themeCorrectionKindMismatch` 检查，拒绝不合法的历史更正映射；实际 `_call` 将该单元记为 failed，保留 rejected 尝试，不把错误响应存为 completed，也不为同一不兼容映射继续请求。仍可发布已经独立验证的当前主题。恢复读取 failed 单元后走相同退路，不重复模型调用。
5. **分组失败可有限重新分组。** 第一层被遗漏/阻止的 supported 事实增加内部 regroup 标记，在现有持久化预算内最多执行一轮重新分组及独立审核。提示模型把关系不清的不同事件拆开，同件事仍归纳。事实证据和纠正核验不放宽；重新分组也无法核验的部分仍保留阻止/遗漏记录。
6. **上层合并失败不抹掉已通过子主题。** 多层归纳的上层遗漏、单元耗尽或预算不足时保留已经审核通过的子主题，停止继续向上压缩。没有把每轮或每句都固定变成一张候选卡。
7. **澄清无纠正场景的谓词。** 提示词明确 `correctionsResolved=true` 表示没有尚未解决的纠正；不涉及纠正不能仅因“不适用”而返回 false。提示词版本更新为 v4。

## 未放宽的边界

- 账号/数据空间、当前证据哈希、成员身份、历史目标版本及提案绑定仍校验；不可识别的数据库/程序/权限错误继续抛出。
- 关系单元即便重试耗尽，目标或成员绑定错误也不降级成发布成功。
- 当前事实无依据、事实已撤回/被取代、明确纠正未解决，不能借关联退路发布。本轮没有删除部分事实的全上下文纠正安全检查。
- 有效的重复仍可 `noChange`，已验证补充仍更新原待确认，明确更正仍需正确绑定和用户确认。失败关联的退路不会直接修改正式记忆。
- 重组使用原有总预算、单元预算和并发限制；未扩大供应商容量限制或预算。

## 本轮未改与后续边界

历史检索“精确重合优先、其后最近八条”、iOS 180 秒状态观察期限、客户端终态文字、测试工具的全关键词规则均未改。停止无效关联页可减少调用，但不是已证明解决全部耗时。底层模型超时重试仍按既有预算，不能宣称外部超时已经消除。

首次现场更正映射的具体事实对及历史 seq5 首发原因仍未完全还原。本轮修复有当前源码和受控反例依据，不把策略修复等同于历史每次失败的精确首因已查明。

数据库验收使用新建隔离库和真实迁移。先创建并确认历史主题，再执行每个新场，故不是空历史测试：

- 短场 A：2 条消息、1 项事实 → 1 张待确认 → 1 条正式记忆。
- 逻辑十分钟：20 用户轮 + 20 助手轮、20 项同事件事实 → **1 张待确认** → 20 条底层正式事实；不是 20 张用户候选卡。时间戳覆盖约十分钟，运行没有等待物理十分钟，也未验证 SDK/音频计时。
- 短场 B：2 条消息、1 项新事实 → 1 张待确认 → 1 条正式记忆。
- 每场均核对事实集合、来源 Source、历史正式版本完全不变、待确认可读、确认成功、重建存储对象后的正式记忆回读；普通 Worker 再轮询不重复发布。
- 有效补充、更正、重复保持的断言在定向回归中通过；本轮 PG 新场重点注入 uncertain，未把所有模型异常都声称已做 PG 验证。
