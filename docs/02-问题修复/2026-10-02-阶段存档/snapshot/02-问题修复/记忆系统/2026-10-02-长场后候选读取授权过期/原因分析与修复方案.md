# 长场后候选读取授权过期：原因分析与修复方案

2026-10-02；DJ-LIVE-REVIEW-POLICY-20261002。以本场手机结果、产品代码和同断言复现为依据，不把授权读取失败解释为模型没有生成记忆。

## 1. 原因和边界

本场 21 轮、42 条正文保存完整，服务器已发布 4 个主题、36 个候选成员。约开场 816 秒，自动验收读取 Source 之前收到 `capturedPolicyExpired`，未发送确认业务写。十分钟自然收尾与候选发布的通过证据保留。

实际 Client 的 Source 列表、详情只检查开场捕获的 route decision，过期直接失败；主题列表也复用该 decision，并把策略拒绝混同为 `accountScopeChanged`。正式记忆读取已有有限刷新机制，但这三个入口未接入，构成接口间恢复行为不一致。即使全局已有新策略，旧 route 的 expiresAt 校验仍先拒绝。

自动工具直接走产品 Source 读取，长场把这个缺口稳定暴露出来。普通档案页入口会重新 capture route，因此不能声称所有用户进入页面都必然失败；但停留后刷新、Source 读取和主题请求仍可能遇到相同过期状态。本次不是火山/DeepSeek 的容量或超时证据，不新增模型调用来验证本地授权。

## 2. 修复约束

1. Source 列表、详情与主题列表接入既有 `boundedOwnerTruthRead`，使用各自诊断资源名称；绑定当前 AccountLease 和 vault。
2. 仅对已有过期/版本变化原因恢复：先按当前策略获得新请求授权；仍过期才最多刷新一次策略。沿用原 30 秒总期限、GET 上限与认证恢复预算，不延长策略寿命、不把真实 deny 改为 allow。
3. 读取成功不能靠改写全局旧 route 来解锁写入。主题预览/确认在各次动作发出之前按当前策略独立 capture 并校验 lease；拒绝准确返回 featurePolicyDenied。两类 POST 均保持禁止自动认证/策略重放，确认结果未知仍保留既有曝光分类。
4. 账号轮换、vault 错配、策略关闭、刷新失败、超时、迟到响应必须拒绝或丢弃。保留原业务参数、Source/成员/提案绑定以及确认前校验。
5. 不修改十分钟收尾、候选发布、分页、模型 prompt 或自动测试通行条件，不处理历史任务。

## 3. 本地验收

- 同一业务断言修前红、修后绿：模拟已经允许的开场 route 随时间过期；通过真实 FeatureGateService、产品 Client 与受控 HTTP，验证 Source 和主题读取可恢复，不使用直接返回 allow 的替身。
- 分别验证当前策略已新鲜无需联网刷新，以及缓存过期只刷新一次；准确解码 Source/list/theme 并核对实际 GET 路径、次数、无 POST。
- 真实 deny、刷新后仍 deny、刷新失败、账号轮换必须无资源请求；已有有限读取期限及迟到结果隔离回归通过。
- 主题写入使用当前授权；真实 deny 准确分类；401/未知结果不重发 POST。
- 回归正式记忆读取、主题编辑与十分钟收尾；检查测试产物实际通过数、失败数和构建指纹。

## 4. 后续现场验收

本地通过与现场闭环分开。本轮不默认重试上次确认或历史任务。后续安装同版后先独立短场门禁，再新开自然十分钟场，逐项验证 Source 读取、主题可见、确认正式记忆与冷启动读取。长场保留超过授权有效期的真实等待，不能提前刷新伪造结果。声学麦克风/扬声器验证另列。真实 Provider、部署、手机未执行均标 NOT_RUN；不因手机未连接停止本地修复。
