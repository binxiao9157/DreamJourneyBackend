# 问题登记与验收维护规则

唯一当前状态入口：[DreamJourney问题登记册](DreamJourney问题登记册.md)。原始报告是证据，不以覆盖或改名方式抹去历史。

## 工作流程

1. 开始调查/开发前查登记册：复用既有问题编号；同表现但不同根因用关联新编号。不要把每次测试失败都登记为新产品bug。
2. 新问题先留事实：时间、场次和版本、失败阶段、预期与实际、脱敏证据。未知根因明确未知，假设与事实分开。
3. 确定修改范围后链接设计、受影响模块、保护清单和同断言红绿计划。修复长场必须保护短场链。
4. 每次交付先更新登记册，再给用户交付报告。缺证据就登记“待核验/未决”，不要用测试总数替代具体断言。
5. 状态变化追加日期、版本、证据与旧→新状态；已解决项保留。如有新回归，记录首次失败版本、回归范围和关联历史修复。

## 状态如何使用

| 状态 | 含义 | 不能代替 |
|---|---|---|
| 待修复 | 已有故障/风险/缺口，实施或根因未闭合 | 重启恢复、只改提示不是关闭 |
| 本地已修待现场 | 适用受控本地断言通过，现场/模型边界未完成 | 真机PASS或生产稳定 |
| 历史真机已通过 | 指定旧版本和场次有明确DEVICE_PASS | 本次发布验收 |
| 本地专项已关闭 | 测试工具或局部断言已闭合 | 产品/全部后端/外部全绿 |
| 待核验 / 首因未决 | 证据不够判断或还原首因 | 确认缺陷或确认正常 |
| 观察项 | 尚无稳定反例或因果证据 | 持久化故障根因 |
| 基线待维护 | 对照证明既存的维护债 | 可以删除断言或称全量PASS |
| 验收待办 | 尚未执行的验收，不等同于已知代码bug | 修复已完成或当前仍必然失败 |

任何问题均应分别写本地、隔离PG、真实Provider、部署、设备、物理时长、声学和历史处理的状态；不适用写N/A，不以一个PASS覆盖所有层。历史NOT_OBSERVED不是FAIL，也不是PASS。

## 保存链的固定验收要求

- 修改任何实际依赖后，以最终源码/配置/构建指纹决定旧证据是否仍适用。复用必须有依据，失效则重跑受影响项。
- 长场前必有同版独立短场门禁：两轮，第二轮补充第一轮；正文及同场身份准确，候选可见，经授权审核后正式记忆可读且重建不重复。
- 本地需要长短联合验收时按 `short-A → logical20 → short-B → logical40`；短场失败停止对应长场。
- 验证逐轮Source/turn/span/evidence/hash、停止尾段、跨批重复/补充/纠正/撤回、B7、候选→审核→正式→回查；不是有HTTP201或pendingReview就算完成。
- 默认API lifespan、官方Worker、真实Client/Controller/Coordinator/磁盘/FeatureGate和隔离PG不能用成品extractor替代；模型受控HTTP必须明确标识。
- 真实Provider、物理时长和麦克风扬声器另验。本地工作完成即可按准确状态交付，不连接、不等待手机；真机由用户主动发起。
- 不增加固定延时掩盖完成屏障，不扩预算或重放未知业务写，不删除恢复坐标，不提前显示成功。
- 基线失败需同环境旧/新最小对照；测试装配失败与业务失败分列。不能仅引用报告的分类就判基线。

## 每次交付给 Sol 的固定要求

> 先读问题登记册并确认本次编号及最新证据。仅实施本次授权范围，保护已通过的保存链。交付时同步更新登记册：具体改动、红绿证据、受影响回归、源码/构建指纹、各环境状态、尚未满足断言和下一动作。已修历史保留，不因一个新失败整体改成“未修”。不把本地PASS当真机PASS；每次长场前独立短场门禁。手机测试由用户主动发起，不以无手机中止本地工作。未获本次授权不调用真实Provider、不部署、不操作生产/历史、不commit/push。

## 文档归档规则（2026-09-30）

- 具体问题的分析、修复方案、开发记录和专项验收放`02-问题修复/分类/日期-问题`。只有架构调整放设计目录；架构实施中发现的缺陷单独登记，双向链接。
- 原始日志、失败记录、xcresult与运行脚本保留outputs。记录问题编号、方案、实施证据和状态，不因移动文档改变历史结论。
- 新链接使用归类后的实体路径；旧路径保留兼容跳转。

## 真实模型交互验收（2026-09-30 用户新增要求）

修改提示词、结构合同、关系/证据语义、模型请求参数时，开发阶段必须同时检查真实供应商，不把受控模型PASS作为发布门禁的全部依据。优先使用新合成数据、实际适配器和生产参数，不读取私人原对话或创建业务任务。事先限定调用组数和预算，保留每次失败，禁止反复重试直到碰巧通过；范围及额外付费调用遵循当轮用户授权。

真实模型检查应覆盖正例和不应放行的结果，独立/重复/补充/纠正须按适用条件验证。仅某次模型返回通过不证明所有输出都正确；严格类型、身份/证据、摘要支持及不确定保护继续由代码执行。真实Provider、部署、真机和声学验收仍分别记账。当前链路的每次长场前独立短场门禁继续保留。
