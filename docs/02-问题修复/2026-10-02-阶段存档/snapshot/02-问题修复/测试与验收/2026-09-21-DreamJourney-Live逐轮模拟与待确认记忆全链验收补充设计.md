## 2. 两个不同的正确性目标

### 2.1 对话完整保存

每个准入的用户/助手观察事件都应有明确归属和处理结果。满足终态条件的回合进入同一场的持久化记录与服务器正文；重复回调不能重复写入，合法终稿修订遵循现有封存合同。真实未完成内容、冲突和落盘失败保留原有partial/争议语义，不伪造成完整正文。

### 2.2 记忆整理正确

**一轮对话不等于一条待确认记忆。** 相同事实跨轮重复应合并，后续补充应保留，明确纠正以正确版本呈现，撤回按既定规则处理。纯问题、助手回答不能冒充用户事实。同一轮可以包含多个独立事实，最终候选也不能被强行限制成一条。

对正常完整场次先证明每轮正文完整，再依据独立事实真值表核对最终候选。不能以“候选条数等于回合数”或“总数增加”代替内容验证。场内预整理仍执行既定分批规则，候选在会后完成校验并统一发布；本验收不要求边说边向用户发布候选。

## 4. 本地实际装配

```text
合成Provider原始事件及可控调度
  → 与生产共用的事件解析/分派和Manager入口
  → 真实Echo Controller / Coordinator
  → 独立临时磁盘Outbox和恢复记录
  → 真实FeatureGate / BackendClient / HTTP
  → 隔离后端生产路由 / Store / Worker
  → 受控模型HTTP响应 + 真实解析、证据校验、分批合并
  → 隔离PostgreSQL中的本场候选
  → 真实iOS候选UseCase / BackendClient / 列表Controller或展示模型
  → 隔离候选审核、正式记忆、客户端/Store重建后回查
```

允许替换：麦克风/外部SDK事件来源、模型HTTP响应、网络故障、可注入时钟及文件故障。真实业务判断、序列化、归属校验、封存、重试预算和候选发布不得由fixture代替。

`ForTesting`入口必须复用生产解析/身份绑定逻辑。若它直接接收已规范化事件而绕过原始Provider事件映射，补一组真实dispatcher映射测试，明确两类覆盖的衔接；不能仅因方法名有Manager就称SDK输入合同已覆盖。

普通本地成功场景可使用隔离测试身份与受控允许策略。TTL、deny、认证恢复、账号切换场景必须驱动真实FeatureGate决策与BackendClient行为，不能以永久allow或refresh直接返回true替代。

隔离数据库允许播种合成账号、必要策略和少量历史对照数据；被测场次的消息、end、ACK、admit、Source和候选必须全部由真实调用链产生，不可手工插入“已完成”记录。任何本地工具不得连接生产、读取真实用户对话、加载真实模型密钥或调用付费Provider。

## 5. 场景数据、时钟和独立预期

每个场景固化一个可重放的合成数据包，至少含：

- 场景版本、种子、逻辑时间表、轮次角色、原始事件类型/字段、身份、回调到达及执行顺序、停止位置。
- 应保存的完整回合正文摘要和partial/重复/争议处置预期；不要将模型提炼后的文字当作原文证据身份。
- 独立事实清单：首次出现、后续重复/补充/纠正/撤回、证据所在轮次、最终候选归属及应排除内容。
- 模型响应脚本及请求断言：实际提交正文/证据ID、批次边界、输出合同、分页和预算；响应不得替缺失输入补回事实。

正常流逐轮注入，不一次性把完成后的Source塞进数据库。单独的突发/迟到场景允许多包排队，以覆盖真实时序窗口。受控时钟推进必须触达生产调度器、策略与凭证过期判断，仅修改capturedAt不算TTL验证。

按事件完成信号和有界条件等待推进，避免新增固定sleep或“等得更久就通过”。超时输出首个未完成阶段及最后持久化/服务器确认水位，不无限等待。记录本机实际耗时即可，不预先承诺固定秒数。

## 6. 同一场的逐阶段断言

| 阶段 | 必须核对的实际结果 |
|---|---|
| 入口 | 事件准入、账号/场次/generation/question/reply绑定，重复与旧事件处置 |
| 本地落盘 | 从真实磁盘读回角色、canonical身份、版本/摘要与顺序；重建Store仍一致 |
| 上传与确认 | 原命令ID、实际请求正文及服务器确认；无丢失、无串场、无重复业务效果 |
| 停止交接 | stop水位内应处理事件全部有处置，close manifest/intent持久化，正常场end/ACK/admit成功 |
| 服务器正文 | 同场所有合法回合逐条对账；包括第13轮之后、中段、后半场和停止前最后一句 |
| 分批与Worker | 实际单元边界、请求输入覆盖、预算、校验、合并结果；全场完成前不提前发布最终候选 |
| 候选落库 | 候选内容、维度和sourceRefs符合事实真值表；重复不增加、补充不丢、纠正/撤回和B7保持 |
| 客户端可见 | 真实客户端读取本场候选，页面/展示模型包含正确正文和来源；历史场不可替代本场结果 |
| 正式记忆 | 沿用真实隔离审核接口，检查正确绑定、正式记忆、幂等及重建回查；不靠直接SQL插入 |

逐轮账本只记录安全关联标识、角色、序号、摘要、阶段及断言结果；合成夹具可单独留存。摘要以同一编码和规范化合同计算，不能用摘要相等替代候选语义真值表。

允许流式同步暂时落后，但必须在场景规定的排空点收敛。故障场景应按自己的安全结果验收，例如未知写保持核实状态；不得为了让所有用例都出现候选而重放未知写或提前成功。

| 编号 | 场景 | 核心通过标准 |
|---|---|---|
| SIM-01 | 两轮补充短场 | 两轮正文和助手上下文保存；本场候选包含事实与补充，真实客户端可见，隔离审核/正式记忆/重建通过 |

| SIM-04 | 逻辑65分钟、150+用户回合 | 同一链覆盖首中尾，输入总字符数/估算tokens/批次数可核查；模型每次输入有界，整体保存不按单次整理条数截断；不冒称物理65分钟 |
| SIM-05 | 跨批重复、补充、纠正、撤回及多维度 | 前后事实确属不同生产整理unit；重复保留两处证据但不多建候选；补充合并，纠正/撤回正确；事实+问题仅事实进入候选 |
| SIM-06 | SDK重复/修订/交错/迟到 | strict final、ASREnded/QueryConfirmed边界、Chat/TTS交错、旧generation和完成reply重放；合法下一轮继续保存，助手不升级为用户事实 |
| SIM-07 | 停止、页面退出及恢复 | 停止前入队但延迟执行的正文不丢；水位外回调不能跨场；同场读回、离开重进、Store/Controller重建归属正确；半句停止仍诚实partial |
| SIM-08 | 真实HTTP链的确定拒绝和未知写 | 分别注入可证明未执行业务的认证拒绝、服务端已保存但丢响应；按现有合同恢复原命令/只读核实，不额外扩大预算，不制造第三次POST |
| SIM-09 | TTL、策略deny与账号切换 | 同账号恢复可继续；明确deny有界停止；切换账号后的迟到回调不发新写，不消费重试预算，不展示旧账号候选 |
| SIM-10 | Worker迟到及候选读取 | 保留已有第7次GET迟到完成等断言；UI不能提前成功或永久依赖重启；同场候选落库但客户端解析/过滤错误时测试必须失败 |
| SIM-11 | 模型交互错误合同 | 在受控HTTP边界注入截断、非法schema、证据遗漏/无效引用、分页补充、429/超时等既有分类，核对typed阶段、有限预算及恢复坐标；失败Run不得再次调用Provider |
| SIM-12 | 验收工具能发现真实错误 | 故意漏一条中段/尾段、错绑一个Source、隐藏客户端一条候选、替换过期short receipt，各自命中独立断言；恢复正确输入后同断言通过 |

SIM-03/04每次启动各自先跑SIM-01，不能用一个旧短场结果覆盖以后所有长场尝试。对CAP单元反例的快速诊断不强制先跑整个短场，避免妨碍开发定位；不得把诊断结果标为长场验收PASS。

短场重建后列表不要只以“总数为1”断言，必须绑定本场Source及事实。同样加入少量**隔离**旧场候选，证明列表分页、过滤或历史状态不会掩盖当前场。不得为此向生产账号重新制造杂乱候选。

## 8. 防止受控答案产生虚假通过

受控模型只能替代外部响应，不得事先把整场正确答案写入候选、隐藏前批重复，或对没有收到的事实仍返回有效证据。每次模型请求必须校验真实输入，响应严格绑定该批所见证据；生产代码负责合并及全场校验。

事实真值表、期望回合账本由场景作者独立定义，不能由被测整理结果反向生成。SIM-12的负例应证明：缺失内容即使总条数不变、状态仍是pendingReview，也会失败。它们验证的是测试工具能检出问题，不代表新发现了生产缺陷；已有生产缺陷另留修前红测/修后同断言绿测。

容量与超时的本地验收记录实际请求次数、每批字符/估算token、配置上限、finish_reason和受控故障，验证本方分批及错误处理。真实供应商当前限制、真实输出质量、音频识别和网络长连接表现仍需后续独立Provider/真机验证；本文件不假定其一定可用或无限容量。

## 9. runner、证据与短场凭证

统一入口应完成：隔离环境检查 → 本次源码/测试包/配置/迁移/模型夹具指纹 → short → 短场完整结果 → 指定long → 受影响回归 → 报告 → 停止本次隔离服务。交付中给出实际可复制的运行命令及参数，不只写概念步骤。

short receipt至少绑定：runID、short场次/Source、最终构建指纹、实际配置摘要、迁移和夹具版本、候选正文/客户端可见/正式记忆/重建断言、完成时间和目标longAttemptID。启动long前重新计算实际依赖摘要，不能只比较两份缓存字符串；一次long尝试后不能复用为下一次放行依据。任何相关变化使旧凭证失效。

受影响依赖至少覆盖采集适配器、Controller/Coordinator、Outbox、BackendClient、FeatureGate、候选读取逻辑、后端路由/Store/Worker/整理、迁移、关键配置、模型夹具和runner。证明执行二进制确实来自所记源码；不得将旧测试包与新源码指纹拼接。

报告逐项提供：场景及种子、实际用户/助手回合数、逻辑时长与墙钟耗时、首个失败阶段、Source/候选绑定摘要、短场先于长场的证据、xcresult/后端结果/隔离PG读回、客户端可见性结果、完整回归映射。阶段日志遵循现有脱敏合同，不打印真实凭证、账号或用户正文。
