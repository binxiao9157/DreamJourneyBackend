# DreamJourney Live 候选整理 run-03 独立复核结论

日期：2026-09-19。

## 放行结论

**认可本次限定范围的 `LOCAL_PASS`。上轮 run-02 复核 §3～5 的实质剩余项已经补齐，未发现需要继续阻断本地交付的问题。**

这意味着本地开发和验证可以结束，不继续等待手机。真实 Provider、真机、部署、历史重处理均未执行；本地通过不等于历史现场问题已经真机关闭，也不代表新代码已在生产生效。

## 复核范围和方式

- 读取 run-03 完整报告、BE/IR 矩阵、红绿记录、最终日志及当前代码。
- 核对 11 个源码/测试/脚本文件哈希、2 个构建产物哈希，均与 run-03 指纹一致。
- 后端生成响应文件与 iOS 输入夹具哈希一致。
- 独立重跑 5 项后台关键定向测试，全部通过。
- PostgreSQL 和 iOS 以脚本/测试实现、最终执行日志及对应指纹交叉核对；本次复核没有重新启动 PostgreSQL、运行全部 iOS 测试或操作真机。
- 没有修改产品代码、访问生产、调用真实 Provider、处理历史数据或 commit/push。

## 已闭合的剩余项

| 领域 | 本次确认 |
|---|---|
| 默认阶段日志 | 真实默认出口向 stderr 输出安全 JSON，不依赖外部 logger 初始化 |
| 支持验证时点 | `supportValidated` 在完整语义与证据复核成功之后发出，失败不会提前发成功事件 |
| 响应类型 | `finish_reason` 非 None/string 返回固定 typed failure，不再误入普通暂态重试 |
| 恢复历史 | 后续 attempt 仅接受固定请求暂态白名单；非法历史不能提供原合同反馈 |
| 数据库竞争 | 两个独立 Store/Worker 在受控 HTTP 门障下竞争，第二个不能获得同一活动 lease，只有一份提交结果 |
| 事务回滚 | 真实 consume 后注入故障；候选、extraction、inbox、completion receipt 回滚，operationAccepted 保留；原 job attempt2 恢复后仅一份结果 |
| 权限与事务占用 | HTTP 等待时改变 authority epoch 后禁止候选提交；门障处数据库活动检查无 idle-in-transaction |
| IR-02 | failed/quarantined 的观察写盘故障保留原恢复依据，正常保留不进入删除待办，不新增业务 POST |
| IR-05 | pendingReview/empty 清理第 1、2、3 步分别故障，终态不回退；下一次合法同场读取可幂等完成清理，无业务 POST |
| IR-07 | FastAPI 真实状态路由生成响应，经过 URLProtocol、BackendClient、FeatureGate、Coordinator/RecoveryService 和 Controller 验证四种状态，每种一次只读 GET |

run-02 已通过的候选→审核→正式 Memory/Version→仓库重建读取与幂等，以及 failed 冷启动主链继续保留。run-03 没有重做或回退它们；已撤销的中间冷启动清理方案不属于最终实现。

- 后端全仓本轮未重跑。run-02 的 2619 项、7 项已独立证实的旧路由计数失败保持原口径，不能改称本轮全仓全绿。
- run-02 UIQA、数据库正式记忆正常链是保留的既有证据，不计为 run-03 新执行次数。
- 超长 support 输入限制、历史 UI 仲裁等独立事项不在本次限定修复中，不因本次 LOCAL_PASS 自动关闭。

## 文档校正记录：不阻断本地放行

run-03 矩阵部分 RETAINED_PASS 行的说明再次与原编号错位。应以原设计及 run-02 的原场景定义为准，不重新定义编号：BE-01 为两轮短场，BE-02 为长形状完整输入，BE-04/05 为组织/支持首次失败恢复，BE-09 为 B7 纯问题，BE-10 为纠正/撤回，BE-13 为同场状态与候选一致性；IR-03 为销毁重建，IR-04 为离页/迟到/账号隔离，IR-06 为 V1/V2 等兼容保护。

该表述问题不推翻已核对的具体测试及保留证据，不要求因此重开产品开发。后续转交时请同时附上本复核说明。

另有五处准确口径：

- correlation 是哈希关联，不能写成“随机值”。
- 非法后续历史被拒绝的是恢复反馈上下文；不会因此重新授予或扩大 attempt 预算。
- 后端输出与 iOS 输入夹具文件字节一致；测试传输中存在 JSON 对象重新序列化，因此应称“同一后端响应合同贯穿控制链”，不宣称传输全程字节顺序不变。
- IR-02 实际通过损坏 follow-up 数据使 observation 保存失败，不是故障 FileManager 模拟写失败；仍有真实失败分支与原记录不删除的证据。
- IR-05 证明的是下一次合法同场 Capture 读取后幂等收尾，不能描述成自动冷启动清理，或同一实例失败后自动重试。

## 下一阶段

本地任务正常结束，不检测、不安装、不等待手机。用户后续主动发起验证时，再核对并发布对应后端、安装对应 iOS 版本，先短场后物理至少 20 分钟长场。

两类场景均按原清单验证：本场内容完整→待确认候选可见→用户确认→正式记忆可查→冷启动仍在且不重复。短场保留第二轮补充；长场保留至少五项首中尾事实、后半补充和明确纠正。不能仅凭保存提示或候选数量判定通过。
