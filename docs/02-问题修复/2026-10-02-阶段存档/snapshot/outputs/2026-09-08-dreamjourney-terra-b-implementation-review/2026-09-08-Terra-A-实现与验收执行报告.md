3. **发布制品：** 安装或提供现有受控 Docker/OCI 构建运行时，并明确服务器 CPU 平台和制品发布路径。先构建带唯一指纹的镜像，再在隔离配置验证 API/Worker。
4. **部署来源：** 只有上述门禁通过后，才需要单独确认本次已验证工作区怎样进入受控 Git 发布来源。部署范围本身已获“门禁通过后”的授权，但未经明确 Git 授权，不能提交、推送、使用旧 `main` 或临时文件复制绕过发布流程。
