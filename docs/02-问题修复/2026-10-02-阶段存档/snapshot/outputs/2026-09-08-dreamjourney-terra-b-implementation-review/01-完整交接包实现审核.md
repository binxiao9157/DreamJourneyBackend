## 3. 需要修复的实际问题

### 3.1 [P1] 更正待确认记忆后，新事实激活会报错

**影响：用户不是直接“确认”，而是先修改内容再确认时，可能再次遇到无法写入正式记忆。**

V5 激活器虽然已取得不可变 corrected value，但在操作被判断为 `add`、`temporalChange` 或 `dispute` 时，调用旧 `build_memory_activation_plan` 没有传递 `corrected_value` 和 schema。被调用方看到 `CORRECTED` 决定却没有这些参数，直接报错。

证据：[V5 新建激活分支](/Users/gaominge/Documents/Codex/Video/DreamJourneyBackend/app/domain/owner_truth/memory_changeset_activation.py:294)、[被调用方强制检查](/Users/gaominge/Documents/Codex/Video/DreamJourneyBackend/app/domain/owner_truth/memory_activation.py:118)、[PostgreSQL 路径调用同一激活器](/Users/gaominge/Documents/Codex/Video/DreamJourneyBackend/app/services/owner_truth_candidate_review.py:2033)。

本地反例 `P01`：更正“喜欢”为“不喜欢”，执行实际 review service，得到 `OwnerTruthMemoryActivationError: corrected decision requires an immutable corrected value`。这是领域/内存仓储实测；没有把它冒充真实 PostgreSQL 结果。

修复验收：首次更正后新增、时间变化、争议以及重放都能正确激活；immutable correction、receipt hash 与最终内容一致；失败时审核与事实事务一致回滚。

### 3.2 [P1] 用户更正文字后，结构化事实仍可能保留原来的意思

**影响：用户看到“不喜欢”，系统用于合并/检索的字段却还是“喜欢”，正式记忆内部自相矛盾。**

iOS 修改的是主文本，保留原来的 `object`、`predicate`、`qualifiers`。后端 canonicalize 重建旧 semantic envelope，但 V5 仍优先保留传入的对象和肯否字段，没有保证它们与新文本一致。

证据：[iOS 更正命令](/Users/gaominge/Documents/Codex/Video/DreamJourney_dev/DreamJourney/Sources/Domain/OwnerTruth/OwnerTruthContracts.swift:14009)、[V5 保留结构字段](/Users/gaominge/Documents/Codex/Video/DreamJourneyBackend/app/domain/owner_truth/ontology.py:692)、[canonicalize](/Users/gaominge/Documents/Codex/Video/DreamJourneyBackend/app/domain/owner_truth/ontology.py:758)。

本地反例 `P08`：存在同类正式事实时，把候选改为“我在杭州时不喜欢吃东坡肉”，审核成功，当前版本持久化为：

```json
{"statement":"我在杭州时不喜欢吃东坡肉","qualifiers":{"polarity":"positive"}}
```

这里“持久化”是实际内存仓储的正式版本历史，不是生产数据库查询。`P01` 同时证实这个不一致内容通过了 V5 校验。

修复验收：编辑主文本后重新生成待审核的受影响结构，或明确使旧结构失效并阻止直接入库；新结构必须再次让用户确认。不能只补 3.1 的参数后就宣布更正完成。

### 3.3 [P1] “补充细节”会覆盖已经确认的更强事实

**影响：“最喜欢东坡肉”可能被之后一句“喜欢东坡肉”降成普通喜欢，用户并没有要求取消“最喜欢”。**

比较器只要对象、范围和肯否一致、内容不完全相同，就进入 `refine`；没有校验它确实是在填补原来未知字段。激活器对 refine 使用整个 incoming content，仅合并 provenance，原来的已知限定随之被替换。

证据：[同肯否即 refine](/Users/gaominge/Documents/Codex/Video/DreamJourneyBackend/app/domain/owner_truth/memory_changeset.py:510)、[refine 优先新载荷](/Users/gaominge/Documents/Codex/Video/DreamJourneyBackend/app/domain/owner_truth/memory_changeset_activation.py:345)。

本地反例 `P02`：先确认 `superlativeAsserted=true`、`strengthExpression=最喜欢`；再确认普通“喜欢”。结果同一个 memory 产生 v2，v1 为 superseded，v2 的两个限定变为 `false`、`null`。

修复验收：refine 只能无损补充未知内容；改变已有意义必须提供明确差异、更正/冲突操作和审核依据，不能静默选择最后一次输入。

### 3.4 [P1] 不同人物的事实仍会在派生合并时混为一条

**影响：“我喜欢什么”和“我父亲喜欢什么”可能只剩一个可查询答案。这不仅影响家人贡献，也影响本人讲述在世家人的材料。**

V5 虽有 `memorySubjectId` 和 `claimSubjectId`，但 `person_memory_model` 的归一化记录没有保留这两个主体字段；类型化语义键只使用偏好对象/谓词。后续统一资格函数又只允许 merged group 的 representative 被消费。

证据：[模型归一化字段](/Users/gaominge/Documents/Codex/Video/DreamJourneyBackend/app/domain/owner_truth/person_memory_model.py:231)、[忽略主体的合并键](/Users/gaominge/Documents/Codex/Video/DreamJourneyBackend/app/domain/owner_truth/person_memory_model.py:300)、[仅保留代表事实](/Users/gaominge/Documents/Codex/Video/DreamJourneyBackend/app/domain/owner_truth/formal_fact_eligibility.py:144)。

本地反例 `P05`：在同一 vault 放入通过 schema 校验的两条事实，记忆档案主体相同、事实主体分别是 owner 和 father，偏好与时间相同。结果 group 为 merged，2 条输入只剩 1 条 eligible，另一条被 `semanticGroupNonRepresentative` 排除。

修复验收：事实主体、来源视角、时间/场景进入合并和资格计算；未知主体不得推定为本人；同类事实跨人物不合并、不相互判冲突。不要通过取消权限过滤或取消全部冲突隔离来提高命中。

### 3.5 [P1] Live 回执丢失后的恢复重试不满足幂等合同

**影响：语音聊过了，但补传卡住、关闭水位不齐，整场内容仍可能无法进入待确认记忆。**

客户端持久化了 turn ID 和 command ID，但发送时从最新 receipt 重新组装 expected thread/session version。后端却把这两个版本也纳入 command payload hash。同一回合服务端已落地、响应丢失后，恢复读取获得更高版本，再用旧 command ID 提交就会因 hash 不同报冲突。

证据：[iOS 重建投递请求](/Users/gaominge/Documents/Codex/Video/DreamJourney_dev/DreamJourney/Sources/Domain/OwnerTruth/OwnerTruthContracts.swift:11731)、[hash 包含版本](/Users/gaominge/Documents/Codex/Video/DreamJourneyBackend/app/domain/owner_truth/conversation.py:425)、[PG 重放冲突判断](/Users/gaominge/Documents/Codex/Video/DreamJourneyBackend/app/services/owner_truth_conversation.py:3506)。

本地反例 `P04`：首次回合成功后，模拟丢回执并按已刷新版本重试，得到 `commandId cannot be reused with a different conversation command`。

另外，内存仓储的完全相同请求重放会漏返回新增的 sequence/watermark，结果由 1 变为 null；[重放结果构造](/Users/gaominge/Documents/Codex/Video/DreamJourneyBackend/app/services/owner_truth_conversation.py:1819)。这是一处测试仓储与新合同不一致的问题，不据此宣称 PG 同样返回 null。

修复验收：冻结首次发送的完整请求信封，或设计能安全分离 turn 内容身份与 CAS 前置条件的协议；保持“同 ID 不同内容必拒绝”。覆盖已落库丢回执、进程重启、恢复后补传、重复 end、跨新旧产品会话。不能更换 command ID 重复写入来绕过冲突。

### 3.6 [P1] ChangeSet 在确认时才生成，用户审核前看不到将如何修改旧事实

**影响：界面让用户确认一条候选，却可能在后台修改某条旧记忆；用户没有看到目标、前后差异和依赖。**

实际顺序是 `decide → activate → build_memory_changeset`。候选 inbox 新增了 memoryRevision，但没有完整 proposed ChangeSet；iOS 审核仍围绕单条候选字段。ChangeSet 类型限制 `len(operations)==1`，新 SQL 也固定 operation_index=1，尚不是原文要求的操作集合与依赖合同。

证据：[先决定再激活](/Users/gaominge/Documents/Codex/Video/DreamJourneyBackend/app/services/owner_truth_candidate_review.py:3000)、[激活时生成变更](/Users/gaominge/Documents/Codex/Video/DreamJourneyBackend/app/domain/owner_truth/memory_changeset_activation.py:224)、[单操作限制](/Users/gaominge/Documents/Codex/Video/DreamJourneyBackend/app/domain/owner_truth/memory_changeset.py:326)、[SQL 写死单操作](/Users/gaominge/Documents/Codex/Video/DreamJourneyBackend/app/services/owner_truth_candidate_review.py:1962)。

另一个入口不一致：[访谈候选激活](/Users/gaominge/Documents/Codex/Video/DreamJourneyBackend/app/services/owner_truth_interview_candidate_memory_activation.py:213) 未传 `expected_memory_revision`。单候选新增的 revision 检查不能证明全部会话审核入口已具备同一基线保护。

已有旧批次/原子组逻辑不等于没有价值；但其存在和对应测试，不能代替这次 B 方案的“审核前差异、基线与依赖整体确认”。

修复验收：整理阶段形成版本化 proposed ChangeSet，审核 DTO/UI 展示旧值、新值、对象/时间/来源及影响范围；用户提交绑定提案 hash/base revision/目标版本。旧提案失效应重新审核，而不是确认后临时决定新的覆盖对象。

### 3.7 [P1] PostgreSQL + pgvector 混合检索尚未实现

**影响：目前仍依赖受控近义词和关键词，不能据此宣称完整 B 方案的自然语义召回已经完成。**

检索 service 明确说明 embedding/vector disabled，实际只调用 `search_owner_truth_documents` 的确定性文本回退。扫描 app 与 SQL migration 没有找到向量 schema/索引、embedding 生成写入、相似检索与融合链路。

证据：[检索服务说明及执行路径](/Users/gaominge/Documents/Codex/Video/DreamJourneyBackend/app/services/owner_truth_memory_search_read.py:3)、[实际返回文本搜索结果](/Users/gaominge/Documents/Codex/Video/DreamJourneyBackend/app/services/owner_truth_memory_search_read.py:90)。原 W05 明确要求在同一 PostgreSQL 内演进 pgvector，不是另起一个独立向量数据库。

未获授权调用新的 embedding 供应商，可以把选型/外部模型验证标 BLOCKED 或 NOT RUN；但是现在缺的还包括生产代码、存储和实际执行分支，不能仅标“pgvector 未实测”。

修复验收：合成数据 PoC 锁定模型/维数/版本；embedding 绑定 vault、version、contentHash、模型版本；结构/文本/向量召回与融合可单独观测；权限、争议、删除、陈旧索引最终回源核验。私人材料出网需另获授权。

### 3.8 [P1] 文字历史接入了回答阶段，却没有接入检索前的指代消歧

**影响：直接问“我哪年大学毕业”能找到，接着问“那是哪一年”仍可能找不到所需正式事实。**

`/echo/answers` 先执行 `_build_authorized_echo_context`，随后才读取本场 recent turns，再交给 DeepSeek。历史保存和 prompt 上下文是已实现的，但历史没有用于这一次正式记忆召回。

证据：[先检索后读历史](/Users/gaominge/Documents/Codex/Video/DreamJourneyBackend/app/main.py:16816)。

本地反例 `P07`：使用现有真实搜索实现与合成投影，“我哪年大学毕业”返回 1 个结果，“那是哪一年”返回 0；“我喜欢吃什么”1 个，“那道菜叫什么”0 个。这个反例测的是检索，不是声称真实 DeepSeek 在这四个问题上已测失败。如果前一轮答案已经说出年份，模型可能靠聊天上下文重复出来，但这不等于查询到了此前没说出的正式细节。

修复验收：服务端在鉴权后先读取该产品会话的已完成历史，生成有来源约束的检索意图/实体/时间指代，再查询正式事实。历史只消歧，不升级为正式证据；第三方/家人目标与新话题必须隔离。

### 3.9 [P1] Live 快照不是有预算的紧凑背景，记忆稍多就整体报错

**影响：小样本时可以启动，记忆增加后 Live 可能拿不到任何背景或启动失败。**

当前循环放入全部 eligible facts，同时在 dimensionSummaries 再拼接一遍 statement，最后若 JSON 超过 32,768 字符直接 `formalMemorySnapshotTooLarge`。没有原 W06 要求的容量选择、分层摘要/覆盖预算和预生成缓存链路。

证据：[放入全部事实并重复摘要](/Users/gaominge/Documents/Codex/Video/DreamJourneyBackend/app/services/formal_memory_conversation_snapshot.py:243)、[超过限制直接报错](/Users/gaominge/Documents/Codex/Video/DreamJourneyBackend/app/services/formal_memory_conversation_snapshot.py:308)。

本地反例 `P06`：100 条简短合成偏好输入，当前模型筛选后 91 条 eligible，就得到 `formalMemorySnapshotTooLarge`。这个数字是本样例结果，不是通用“91 条上限”。

还发现新字段 `memoryRevision` 从 projection 读取，缺失时默认 0；当前 projection 生成路径没有同步写入它。[快照 revision 默认值](/Users/gaominge/Documents/Codex/Video/DreamJourneyBackend/app/services/formal_memory_conversation_snapshot.py:285)。已有 checkpoint/hash 不应否认，但它们不能自动证明新的权威 revision 合同已经贯通。

修复验收：限定预算、可验证覆盖、真实权威 revision 与派生 checkpoint 分开；同 revision 可复用快照，新事实能在明确边界刷新。不要通过取消上限、假称热更新成功或恢复逐轮 DeepSeek→TTS 来解决。

原生音频状态机未被本次 diff 改动是正面结果；SDK 是否实际使用新背景、热更新和撤权仍需后续真实合成数据/设备证据，当前不作通过判断。

### 3.10 [P1] 时间范围只做不相等比较，重叠冲突被当作正常时间变化

**影响：同一时间段“喜欢”和“不喜欢”本该请求澄清，却可能并列成为无争议的历史事实。**

比较器在 scope 字符串不相等时直接判 temporalChange，优先于 polarity 检查，没有比较有效区间是否重叠、一个区间是否包含另一个、表达不同是否其实同一时间。

证据：[时间分支优先](/Users/gaominge/Documents/Codex/Video/DreamJourneyBackend/app/domain/owner_truth/memory_changeset.py:465)。

本地反例 `P03`：2016–2020 年喜欢、2018–2022 年不喜欢，同一主体/对象，结果 `temporalChange`，没有识别 2018–2020 的冲突。

修复验收：明确处理区间重叠、相邻、不相交、未知时间和表达归一。变化不应被误判冲突，但不同字符串也不能自动消除冲突。特别注意 `_has_meaningful_scope` 中拼接后的 unknown 时间字符串仍为非空。

### 3.11 [P2] 整体记忆文本与段落证据还没有达到 W07 要求

目前 profile 每次读取全部 current memories 再构建模型，不是按受影响维度维护增量正文。派生正文路径仍分桶、按块拼接模板，尚不能把“已有连续文本”视为此次整体中性记忆设计全部完成。

证据：[profile 每次全量重建](/Users/gaominge/Documents/Codex/Video/DreamJourneyBackend/app/services/owner_truth_person_memory_profile.py:282)、[实际块生成路径](/Users/gaominge/Documents/Codex/Video/DreamJourneyBackend/app/domain/owner_truth/person_memory_model.py:837)。

新增 paragraphEvidence 在 `_life_story_from_model` 中把整章全部 memory IDs/versions 赋给每一段，丢掉原 block 已有的更精细 evidence。这是可定位的证据映射问题，不只是写作风格偏好。[整章证据复制到每段](/Users/gaominge/Documents/Codex/Video/DreamJourneyBackend/app/services/owner_truth_person_memory_profile.py:467)。

修复验收：保留实际 block/段落的证据映射，采用受影响维度的中性整体更新；显式记录依赖版本与 stale 状态。正式概览不是文学润色，自传仍是独立文学派生物，不能回写事实。视觉是否满足用户最终审美留到后续页面验收，不冒充已看过真机。
