## 2. 前置数据与基线

1. 用户通过“记忆档案 -> 封存新记忆 -> 记录文字”提交合成素材：`本次B7档案素材测试使用的未审核代号是青岚二号。`
2. 候选列表从 42 条增加到 43 条。
3. “青岚二号”候选恰好 1 条，详情正常，用户未点击确认、更正或拒绝。
4. 新 Live 开始前的候选基线明确为 43 条。

## 3. 复现步骤

1. 用户在“回响”中新开原生 Live。
2. 问正式记忆问题：`我的测试阅读清单代号是什么？`
3. 系统有声音并正确回答“晨星”。
4. 问未审核素材问题：`本次B7档案素材测试的未审核代号是什么？`
5. 系统回答不知道，未提到“青岚二号”。
6. 用户未陈述任何新事实，随后手动停止 Live。
7. 进入待确认记忆并刷新。

## 4. 预期结果

1. 正式记忆“晨星”可继续用于回答。
2. 未审核的“青岚二号”不得进入正式记忆或 Live 回答。
3. 两个用户问题只是查询，不是新的本人事实证据。
4. 本场应得到 `noChange`，候选总数保持 43 条。
5. 助手回答、问题文本和推测均不得成为候选事实。

## 5. 实际结果

### 正确部分

- 正式记忆回答正确且有声音。
- 未审核的“青岚二号”未被 Live 采用。
- 没有错误、卡住或长时间等待。

### 失败部分

- 手动停止后页面显示“已进入待确认记忆”。
- 刷新前后候选总数均为 45 条，较 Live 前增加 2 条。
- 新增候选分别为：
  - `用户问过本次 B7 档案素材测试的未审核代号是什么。`
  - `用户问过自己的测试阅读清单代号是什么。`
- 两条内容都只是用户提问的转述，不是新事实。
- 用户没有审核这两条候选，也没有要求删除或修补生产数据。

## 7. 已证实与未证实

### 已证实

1. 未审核档案素材没有被新 Live 当作正式记忆回答。
2. 用户只问了两个问题，没有提供对应的新事实陈述。
3. 本场结束后真实候选 GET 从 43 条变为 45 条。
4. 新增两条候选正文都是对用户问题的陈述化转写。
5. 两次刷新均为真实 HTTP 200、typed decode 和 UI commit。

### 尚未证实

1. 问题文本在 iOS 会话打包、后端 Source、Worker 提取器或 proposal builder 的哪一层首次被错误标记为事实。
2. 是否缺失句式/语用分类，还是角色、证据属性或转写终稿边界错误。
3. 是否所有问句都会触发，或只在涉及正式记忆关键词时触发。
4. 是否会把助手回答一并错误写入；本次候选正文只观察到用户问题转述。

## 8. 影响与停止点

- B7“未审核内容不进入正式 Live”：该子项 `PASS`。
- B7“纯问题不生成候选”：`FAIL`。
- B7 整体：`FAIL`。
- 两条错误候选保持原状，未确认、未拒绝、未删除。
- 不继续通过更多相同问句制造生产候选。

## 9. 给设计分析的核查要求

1. 以本次真实会话边界建立失败反例，逐层检查用户角色、问句语义、证据属性和候选 builder 输入。
2. 不能仅用问号或简单字符串过滤；需覆盖无问号疑问句、反问、确认问法、陈述中带疑问引用等边界。
3. 保留真正的新事实陈述、纠正、时间补充和多轮终稿提取能力。
4. 助手回答不得进入正式事实；用户问题不得被改写成“用户问过……”候选。
5. 运行真实后端 builder、隔离 PostgreSQL、iOS 会话打包、受控模型/Worker 和 UIKit 候选读取组合测试。
6. 输出局部修复设计、红绿测试、部署影响、真机复测步骤和回退方案。
