## 1. 仍需修改并红绿：成功/失败事件进入 Controller 后再次异步调度，丢失原 attempt 归属

真实 Manager 的 [deliverProviderCallback](/Users/gaominge/Documents/Codex/Video/DreamJourney_dev/DreamJourney/Sources/Services/DialogEngineManager.swift:5483) 在调用 delegate 之前验证 operation、binding、delegate 和 lease；[SessionStarted](/Users/gaominge/Documents/Codex/Video/DreamJourney_dev/DreamJourney/Sources/Services/DialogEngineManager.swift:5712) 随后调用 `delegate.onDialogStarted()`。但 [EchoViewController.onDialogStarted](/Users/gaominge/Documents/Codex/Video/DreamJourney_dev/DreamJourney/Sources/Modules/Echo/EchoViewController.swift:16619) 再次 `DispatchQueue.main.async`，只捕获 `self`，排队任务执行时读取当前的 `activeVoiceLaunchAttempt` 和 lifecycle token，再记 `sessionStarted`、`finish("listening")`、移交资源和进入 listening。[onError](/Users/gaominge/Documents/Codex/Video/DreamJourney_dev/DreamJourney/Sources/Modules/Echo/EchoViewController.swift:17101) 有同样的二次排队后读取当前 attempt 的结构。

静态可达时序是：A 的事件通过 Manager 校验并排入 Controller 主队列 → 队列中先执行的取消/重开动作把当前启动改成 B → A 的 UI 闭包执行，并错误地完成或失败 B。run-02 新增的 [DEBUG 回调身份校验](/Users/gaominge/Documents/Codex/Video/DreamJourney_dev/DreamJourney/Sources/Modules/Echo/EchoViewController.swift:16195) 同样发生在调用 `onDialogStarted()` 之前，不能覆盖第二次调度期间的换场。

现有 [MIC-05 新测试](/Users/gaominge/Documents/Codex/Video/DreamJourney_dev/DreamJourneyTests/OwnerTruthContractsTests.swift:32933) 是先取消 A、启动 B，然后才调用 A 的回调，证明了入口校验；没有证明“A 回调已接收，Controller 副作用尚未执行”的窗口。最小改动应在事件进入 Controller 时冻结 attempt/生命周期身份，并在实际执行 UI、音频和终态副作用前再次匹配；成功和失败路径都要覆盖。新增可控队列用例分别让 A 的 success/error 已入队，再取消 A、启动 B；断言 B 不被 listening、失败、stop、释放 lease，B 自己的回调仍可完成，A/B 终态各一次。本轮未运行该红绿，也未声称它已复现现场故障。
