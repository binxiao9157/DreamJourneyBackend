## 直接原因与证据链

本场新主题整理和事实支持均通过；themeRelation返回relation=none、targetTopicId=null，表示与既有主题独立。独立复核返回：

```json
{"verdict":"supported","sameSubjectEvent":false,"compatibleTime":true,"correctionsResolved":false,"summarySupported":true}
```

这表示模型认可“独立”的判断，没有认定它与旧主题是同一件事。当前`app/domain/owner_truth/live_theme_relations.py::validate_relation`不区分none和合并关系，在review阶段统一要求四个布尔值都必须为true，因此返回None。

`RecoveryThemeAssembler.relate_themes`把None标成themeRelationUnresolved并阻止该主题进入输出。这里只有一个主题，最终触发candidateExtraction.live.themeValidate.noReliableThemes。数据库作业记录确有此错误码，独立复核已completed仅表示结构验证通过并保存，不等于语义关系被接受。这一点与之前“非法结构缓存completed”的缺陷不同。

该路径已用本场相同枚举及布尔组合、本地合成身份和真实relate_themes方法复现：acceptedThemes=0、blocked.reason=themeRelationUnresolved。本地测试期望独立主题保持可发布而失败；未调用模型或数据库，也未改产品实现。

## 为什么此前本地四场没有拦住

`run-02/final_four_server.py`第80—85行调用controlled_relations的independent模式；其复核返回固定sameSubjectEvent=True、compatibleTime=True、correctionsResolved=True、summarySupported=True，即使提案关系是none也如此。真实模型合理的false组合未覆盖。前述63项定向回归覆盖格式、重复/补充/更正，但没有覆盖none关系的独立复核语义，这是此次遗漏，不可用通过数量抵消。
