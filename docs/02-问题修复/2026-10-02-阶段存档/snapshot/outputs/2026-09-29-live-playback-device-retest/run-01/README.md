## 5. 内外部归因边界

### 已证实的内部状态

- UI/声音状态结束不等于保存链收尾完成；本场两者出现分离。
- 自动测试以语音完成推进下一轮，不能把该轮标记当作持久化/候选证明；已补本次只读逐轮对照文件，而非更改测试实现。
- 第32轮完整语音往返没有对应完整服务器正文对；最终发布所需结束批次和Source缺失。

### 诊断开销是待验证线索，不是定论

现有`NativeLiveDiagnosticsRingStore.recordOnQueue`逐事件读取、解码、追加、编码并写回整个JSON；`snapshot`使用串行队列`sync`。自动测试失败发布先写result，再在主Actor同步导出诊断。

本场已存在的SDK诊断文件约1.27MB，保留4096事件、淘汰3044事件；其中3473条为3018播放器音频回调。失败result已保存而最终diagnostic-events.json未取得；原有环形文件仍在较晚时刻更新。这支持调查诊断队列积压/同步等待是否影响主线程和停止回调。

但没有线程栈、事件入队时间与处理时间差、I/O耗时对照；诊断时间戳是在队列处理时生成，不能把晚写记录当作晚收到SDK事件。尤其失败导出发生在送帧异常之后，不能倒因为果认定它造成最初0.524秒间隔。它至多是后续收尾阻塞的候选解释；日常诊断写入压力是否先影响调度也未证明。

证据：[诊断摘要](long-diagnostic-summary.json)、[本场既存诊断环](long-existing-diagnostic-ring.json)。原始内容已最小化，无对话正文。当前未进一步读取其他场诊断。
