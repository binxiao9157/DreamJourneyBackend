# 修前红测与修后结果

## 产品级红测

1. **认证恢复后的 authority epoch 仍按旧值严格相等**
   - 修前：同账号刷新取得合法新授权后，原 append 被绑定校验拒绝，不能继续原命令。
   - 修后：允许同账号合法 authority epoch 单调前进；thread/session/正文/sequence/版本绑定仍严格，账号切换仍拒绝。
   - 修改：`EchoViewController.swift`。

2. **只读 delivery-status 把旧 receipt 的 authority epoch 当作必须相等**
   - 修前：服务端已经保存、响应丢失后，合法只读核实因新 authority epoch 被拒绝。
   - 修后：保持同 thread/session，并要求 thread/session/authority 版本不回退；不重发未知 append。
   - 修改：`OwnerTruthContracts.swift`。

3. **iOS 与后端 canonical JSON 键排序规则不同**
   - 修前：真实 status GET 命中 sequence 300，但 `sameContent=false`；未知写记录不能安全解决。
   - 根因：Foundation `.sortedKeys` 与后端 Unicode code-point 排序对 `capturedAt/captureMode` 的顺序不同。
   - 修后：iOS 使用与后端一致的 Unicode code-point 排序和 JSON 字符串转义；固定向量 hash 为 `e9a24fab2eebcdbc71f753985a272170746bbb505c630fcc4f3e7640154716fd`。
   - 修改：`OwnerTruthContracts.swift`；新增 `testLiveDeliveryContentHashMatchesBackendCanonicalJSON`。

4. **后端正式记忆查询 SQL 使用错误变量**
   - 修前：重建读取路径把 `thread_id` 传入 SQL，而当前作用域的合法变量为 `current_thread_id`。
   - 修后：使用当前线程绑定变量，正式记忆重建读取通过。
   - 修改：`app/services/owner_truth_conversation.py`。

## 验收工具红测

- 缺失/失败/跨运行 short receipt、配置或构建产物变更均必须在 long 请求前失败。
- 漏中段、漏尾段、错 Source、仅用后端候选数冒充 iOS 可见均必须失败。
- 受控模型收到同 index 但替换正文，或实际请求漏正文时必须失败。
- 这些负例只修验收装配，不扩大产品保存架构。
