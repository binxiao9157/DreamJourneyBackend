# Live 长回答手机端真机验收记录

日期：2026-09-15\
设备：iPhone 14 Pro Max\
验收边界：手机端原生 Live；车机/CarPlay 不作为门槛\
当前结论：自然播放 PASS，主动打断 PASS，停止后状态 NOT_OBSERVED

## 场景一：无人为打断的长回答

用户在回答期间没有插话或操作，环境中没有需要纳入结论的其他声源。

| 检查项 | 结果 |
| --- | --- |
| 回答是否有声音 | PASS，有声音 |
| 是否自然播放到回答结束 | PASS，约 1 分钟完整播放 |
| 是否中途停止 | PASS，未停止 |
| 停音后文字是否继续变化 | PASS，无继续变化 |
| 播放结束后是否自动恢复聆听 | PASS |
| 是否出现错误 | PASS，无错误 |

## 结论边界

- 本场证明手机端约 1 分钟长回答可以自然播放到结束。
- 本场没有发生用户主动插话，因此不证明长回答中的主动打断路径已经通过。
- 本场不能单独替代整场 transcript 持续采集、关闭交接或 B8 文字关闭验收。

## 场景二：长回答中主动插话

用户在长回答有声播放约 20 秒后，未点击按钮，直接提出新的问题。

| 检查项 | 结果 |
| --- | --- |
| 插话前是否持续有声音 | PASS |
| 插话后原回答是否立即停止 | PASS，立即停止 |
| 是否自动听到并回应插话 | PASS |
| 第二个回答 | “你的测试阅读清单代号是晨星” |
| 是否采用正确正式记忆 | PASS，回答“晨星” |
| 是否出现错误或长时间等待 | PASS，无 |
| 手动停止后的状态 | NOT_OBSERVED，用户未注意到明确状态 |

设备诊断显示第二轮问题与回答使用匹配的 provider question/reply 身份，并在回答结束后收到 `ttsEnded`。本场页面行为与诊断共同支持主动打断通过；停止后的会后整理状态未被用户确认，因此不纳入通过范围。
