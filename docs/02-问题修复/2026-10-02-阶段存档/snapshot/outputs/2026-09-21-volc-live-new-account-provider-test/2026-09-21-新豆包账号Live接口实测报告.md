# 新豆包账号 Live 接口实测报告

日期：2026-09-21

## 结论与范围

**PROVIDER_SMOKE_PASS：新账号可以按原鉴权方式、原 WebSocket 地址、`1.2.1.1` 模型参数使用豆包 Live。**

本轮确实向豆包发起了会话和推理请求，不是只检查 HTTP 101。完成了两轮文字输入、两轮连续语音输入，以及一组生成中插入新语音的测试；五个测试场景均得到正确回答和可解码、非静音的音频。两个测试会话及连接均收到正常结束事件。

这不是 DreamJourney 全应用验收，不代表 iPhone 已换账号，也不能替代真实麦克风、SDK 播放、回声消除、用户感知打断或正式记忆绑定验收。

## 固定配置

| 项目 | 本轮值或处理方式 |
|---|---|
| 模型请求参数 | `dialog.extra.model = 1.2.1.1` |
| 默认音色 | `zh_male_yunzhou_jupiter_bigtts`，与当前 iOS 默认配置一致 |
| 连接地址 | `wss://openspeech.bytedance.com/api/v3/realtime/dialogue` |
| 鉴权 | 调用当前后端 `RealtimeVoiceSessionBroker.upstream_headers()` 构造原有鉴权头 |
| 凭证 | 从仅当前用户可读写的独立本地测试配置加载，不写入测试脚本或证据 |
| 语音输入 | 16 kHz、单声道、16-bit PCM，640 字节一包，约 20 ms 间隔 |
| 语音输出 | 保留原默认 Ogg/Opus，接收后在本地解码检查 |
| VAD | 与当前配置一致，1500 ms，自定义 VAD 开启 |
| 语速、音量 | 与当前配置一致，`speech_rate=-20`、`loudness_rate=10` |
| 输入方式 | 文字测试用官方 `input_mod=text`；音频测试不设置该覆盖项，按原默认流式音频方式发送 |
| 测试内容 | 简短合成算术问题及测试专用人设，不含真实用户事实或正式记忆 |

测试器只是替代手机提供输入并接收输出，没有更改 iOS、后端业务代码、默认 `.env`、生产服务或模型配置。

## 实测结果

| 场景 | 输入及预期 | 实际结果 | 状态 |
|---|---|---|---|
| 新账号鉴权及连接 | WebSocket + StartConnection | 101；收到 ConnectionStarted(50) | PASS |
| 模型会话建立 | StartSession 携带 `1.2.1.1` | 两个会话均收到 SessionStarted(150) | PASS |
| 文字第一轮 | 一加一，预期 2 | 文字 `2。`，收到并解码语音 | PASS |
| 文字连续追问 | 再加一，预期 3 | 同一会话文字 `3。`，收到并解码语音 | PASS |
| 语音第一轮 | 合成录音问三加四，预期 7 | 最终 ASR、ASREnded、文字 `7` 和语音均收到 | PASS |
| 语音连续追问 | 同一会话问刚才结果再加一，预期 8 | 最终 ASR、ASREnded、文字 `8` 和语音均收到 | PASS |
| 输出中插入新语音 | 先要求从一数到二十，首个音频包到达后发送“先停一下，二加三等于几” | 两个不同 ASR question；新问题对应回答 `5`，收到并解码新语音 | PASS，限服务端信号与换轮 |
| 会话结束 | FinishSession | 两次收到 SessionFinished(152) | PASS |
| 连接结束 | FinishConnection | 收到 ConnectionFinished(52) | PASS |
| 返回音频有效性 | 不以字节数代替音频验证 | 五个答案都解码为约 0.97 秒 PCM，RMS 约 1119–1694，峰值均非零 | PASS |

注意：语音识别将测试话术中的“只说答案”识别为“知说答案”，但算式及追问含义被正确识别，答案正确。本轮不据此宣称 ASR 逐字准确或所有场景识别质量通过。

### 时延口径

- 两次文字输入至首个音频包分别为 0.607 秒、0.608 秒。
- 两次语音输入至首个音频包分别为 7.455 秒、6.323 秒，**包含输入录音自身约 5.38 秒、4.34 秒的流式上传过程**，不能当作用户说完后的等待时间。
- 打断测试中，从开始发送打断录音至新回复首音频为 5.960 秒，包含约 3.99 秒的录音输入；不是手机播放器停止旧声音的耗时。
- 只有单次冒烟样本，未做延迟分位数、弱网或长时间稳定性评估。
- 成功一轮脚本总耗时约 26.55 秒。

第一次运行已经成功建会话并收到语音，但 Python 3.9 标准 `wave` 模块不能读取系统解码器生成的 WAVE_FORMAT_EXTENSIBLE 文件，导致本地验证器停止。修改的只是测试脚本：改经系统 AIFF 解码、使用标准音频解析器检查采样，再生成普通 WAV。先复查已有输出通过，才重跑接口测试。该次会话和连接也正常结束；它不属于豆包接口失败。

## 安全与后续

1. App ID、Access Token 只从后端 Git 忽略的私有目录加载，Secret Key 未用于测试。
2. 日志未输出鉴权头、密钥、个人记忆或真实对话；报告中问答来自合成测试。
3. 没有创建 DreamJourney 的 session、batch、source、candidate 或正式记忆记录。豆包侧创建了两个临时测试会话，并正常结束。
4. 没有自动打开麦克风，没有使用旧 ASR → DeepSeek → TTS 业务链路。本机 TTS 仅用于生成测试输入文件。
5. 下一步若要让 iPhone 使用新账号，需要另行接入承载这些凭证的目标测试后端，再做 SDK 与真机验证；不能把本报告视为已经切换完成。
