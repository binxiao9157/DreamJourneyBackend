# Live 长对话分批整理：本地验证与后续真机验收

日期：2026-09-20。配套 [开发设计](2026-09-20-Astra-Live长对话分批整理与会后统一发布-开发设计.md)。\
**A 阶段是 Sol 当前必须完成的本地开发任务。B/C/D 阶段只准备，不自动执行，不等待用户手机。**

## 1. 证据规则

- 所有语义夹具先写独立真值清单：用户原话、事实 ID、证据区间、事件身份、补充/纠正/撤回关系、期望最终表达和不应出现的内容。不能由模型输出倒推期望结果。
- 候选数不等于发言数。判定看全部应保留事实、所有排除理由、去重及证据，不以“数量增加”单独判成功。
- 受控模型响应必须是完整 HTTP envelope，经过真实 adapter、schema parser、support、Run/Unit、Worker、UoW、候选审核服务。不能直接注入最终候选或把未覆盖用户发言自动标 query。
- iOS 使用真实 Controller、Coordinator、磁盘、BackendClient 和 FeatureGate，仅替换网络边界与时钟；不得用全部 fake 的链代替产品装配。
- PostgreSQL 必须验证真实唯一约束、并发、事务、重建恢复和预算，内存库不能替代。
- 关键反例记录同断言修前失败、修后通过。已有正确行为做保持性测试，不为凑红测人为破坏代码。
- 每个矩阵项保留：输入夹具版本、命令、结果路径、关键断言、源码指纹和状态。不得用总测试数代替逐项验收。
- 真实 Provider、物理时长、真实 SDK 回调不能由受控 HTTP、注入时钟或模拟器结果代替。

## 2. 必须准备的合成数据集

| 夹具 | 最低规模 | 必须包含 |
|---|---|---|
| F-S | 2次用户发言及助手上下文 | 首次明确个人经历，第二次补充；期望事实与维度；确认后正式记忆 |
| F-R12 | 77总turn / 39用户turn，12个独立事实 | 复现已证明的旧8条容量矛盾，其余为问题；禁止将其称为私人历史重放 |
| F-20 | 逻辑20分钟，至少40用户turn、20个独立事实 | 五个主题，首中尾事实、重复、跨批补充、尾部纠正与撤回 |
| F-DENSE | 逻辑20分钟，至少120用户turn、至少241总turn、至少300个事实原子 | 超过30000字；按事先关系归并后仍超过32个候选；问题和事实混合；多维字段 |
| F-65 | 逻辑65分钟，至少150用户turn、至少301总turn | 跨3600秒；正文超过50000字；至少120个应保留原子事实、最终超过32个候选；前59分钟提出、61分钟后纠正/补充 |
| F-ONE | 单个用户turn超过4000字，包含至少20个独立事实 | 长句、分片边界指代、emoji/组合字符、一个区间多事实 |
| F-AMB | 少量但语义复杂 | 同人不同事件、别名、过去与现在偏好、引述、助手诱导、含事实的问题、明确撤回及无法消解矛盾 |

这些规模是开发验收输入，不是产品承诺的最大会话容量。F-DENSE/F-65 要输出工作单元、关系页数、模型调用和token预算分项统计，证明配置足以完成；不得临时缩小样本逃避预算门禁。

### 3.4 必须保持的历史场景

- BE-01～BE-14、IR-01～IR-07 按旧编号逐项映射；新pipeline新预算断言另列，旧pipeline不被静默改写。
- 70/48积压排空与同账号401恢复、deny有界停止、账号切换迟到回调零新增写。
- B8 ACK后的状态读取、fresh authority、S01-08跨轮旧poll隔离。
- canonical final、非ASR过滤、停止前已登记final排空、partial分支及覆盖摘要。
- 长回答自然播放、主动打断、音频ownership、恢复聆听；手机实际声音仍另验。
- 候选确认/拒绝、正式Memory/Version与读取、重复确认幂等、错误Source/epoch拒绝。

只有真实受影响的实现才扩回归范围，但不能漏共享依赖。已知基线失败必须在修前同环境复现并列证据；不能把全部失败一句“历史问题”带过。

## 4. A 阶段完成门禁

1. LM/LI矩阵全部本地必需项通过，给出对应证据；若某项与最终最小实现确实无关，必须提供代码理由与替代断言，不能自行删关键产品要求。
2. F-S/F-R12/F-20/F-DENSE/F-65/F-ONE/F-AMB 都有真值核对；另用300个互相独立事实验证分页计划，不能依赖大量预判distinct短路才装得下预算。分别报告调用前token预留与实际usage/估算、停止瞬间剩余计划、会后耗时、实时关系预计算及无预整理时补算；健康场次不得被600秒无进展/3600秒绝对保护误杀。
3. 内存、隔离PostgreSQL、默认CLI装配、iOS真实组合、模拟器构建与通用iOS无签名构建通过；完成受影响全量回归及两端diff检查。
4. 本地报告写清哪些旧PASS被触及、如何重新验证；给出最终源码和测试指纹。
5. 准备迁移/Worker/开关发布说明以及以下后续测试脚本，正常结束任务，不等待手机。

报告状态：`LOCAL_PASS / PROVIDER_NOT_RUN / DEVICE_20M_NOT_RUN / DEVICE_65M_NOT_RUN / DEPLOY_NOT_RUN / HISTORICAL_REPROCESS_NOT_RUN`。

## 5. B 阶段：真实供应商验证——另行授权后执行

本地阶段只准备 runner、合成夹具和请求/费用上限，不发请求。每次真实模型测试须明确批准的场景、最多请求、费用估算与停止条件；以前8次诊断额度已用完。

先执行 F-S、F-R12、小规模跨批纠正；再按批准范围执行长场合成集。验证的是当前新pipeline全部请求与独立事实真值，不是仅手动扩大cap做一次成功展示。

记录实际域名/model、请求次数、usage、finish_reason、阶段/字段失败原因、每请求与全场耗时、关系与事实覆盖、去重结果。至少安排重复运行评估波动，但次数须包含在审批的总预算内，不暗中循环直到成功。

供应商返回合法JSON但错误语义、空内容、截断、限流、超时分开报告。没有真实供应商验证时，不能把本地受控网络写成MODEL_PASS。

## 6. C 阶段：用户主动发起的当前真机验收

### C0 前置

确认用户已发起本次测试，再按授权安装/启动；记录设备、App构建指纹、后端/Worker版本、迁移和开关。后端仍为旧版本时不得用新版App单测宣布修复有效。部署不自动包含在文档阅读或本地开发授权中。

每场使用新的合成标记，记录待确认和正式记忆基线，避免修改已有个人记录。审核测试只处理明确指定的本场合成候选，保存拒绝/确认选择。

### C1 短场完整闭环，必须先通过

1. 第一轮讲一件合成个人经历，含独立代号、时间与地点；第二轮补充同行者，并明确更正其中一个值。
2. 确认有声回答及恢复聆听，停止后记录阶段变化；正文保存和候选出现分别记录。
3. 刷新待确认列表，找到**本场代号对应的候选正文**；确认补充完整、错误旧值不再作为有效事实、同事件无重复。对话气泡不算候选证据。
4. 用户按计划确认指定候选；到正式记忆列表/详情查到正确内容和出处。未审核前不得已经存在正式记忆。
5. 冷启动，核对候选/正式记忆、同场状态及记录数量；没有重复候选、重复正式记忆或业务写重放。

### C2 物理至少20分钟长场完整闭环

1. 连续自然交谈至少20分钟，五个主题，至少30个用户回合；独立预设至少15个应保留事实，保证不是只验证旧8条以内样本。
2. 首、中、尾各安排标记；后半重复早期事件、补充细节、明确更正和撤回；加入同人不同时间事件及纯问题对照。
3. 记录实际持续时间、用户回合/总turn、正文字符、预整理单位数和实际候选数。原始音频完整性按预设事实与Source对照，不以计数代替。
4. 停止后完成正文/end/ACK/admit、后台整理、候选正文核对；每项事实具有最终归属。内部草稿不能提前泄漏为候选。
5. 对本场合成候选按计划审核，使预期事实进入正式记忆；确认首、中、尾和修正内容可读，旧值/撤回内容不被错误保留；重启回查无重复。
6. 同时保持长回答自然播放、打断与恢复聆听；观察失败、候选失败、音频失败分别记录。

若本次20分钟实际不足100用户回合，仅能判“20分钟普通密度通过”；100+密度另标NOT_RUN。本地F-DENSE不能冒充真机密集场。当前先20分钟通过，不要求为了本轮验收立即再做一小时。

C1或C2关键失败即完整留证，保留Source/Run/manifest/恢复坐标；不自动清理、重放历史任务或不断开新Live堆积失败场。手机可以按用户安排断开，后续优先回到本地定位。

## 7. D 阶段：以后由用户主动发起的1小时以上压力验收

目标为**物理至少65分钟**，跨过旧3600秒边界；至少120个用户回合，并预设至少60个分布于首、中、尾的有效事实。事实数量与预期候选数分别定义，不能一轮固定映射一候选。

- 59分钟前的事件在61分钟以后补充/纠正；穿插重复、纯问题、明确撤回、多维属性与独立同主题事件。
- 验证同一产品场次、全局序号和最终Source没有因连接/凭据更新分裂；记录实际连接数量与供应商错误，不猜测透明续连已通过。
- 验证预整理在会话中真实推进，正文同步不中断，末尾排空完整；关闭后同场候选、审核、正式记忆、冷启动回查全部闭环。
- 记录Provider调用/预算、处理积压、结束后耗时、设备与服务端资源。供应商上下文遗忘、ASR漏识别、正文漏同步、模型整理失败分别归因。
- 另行安排密集20分钟100+用户回合测试时，单列结果；不能用65分钟较慢聊天替代密集容量测试。

20分钟通过不自动标记65分钟通过；65分钟未执行也不撤销已经完成的本地开发和20分钟证据。

## 8. 禁止的验收捷径

不能增加固定等待后显示成功；不能以候选总数上涨代替本场正文；不能只确认一条就声称长场全部事实进入正式记忆；不能直接插入候选/正式记忆造闭环；不能扩大预算后抹去原预算耗尽结果；不能把partial的正确提示当缺陷；不能把没有发生的401标PASS；不能把用户原对话用于新增付费模型重放而不另行授权。

每次最终报告要把 Source 保存、候选生成、用户审核、正式记忆、重启读取、Provider、音频、物理时长分别列状态。只有实际执行且证据满足的项才标PASS。
