# DreamJourney Live 架构设计定稿

> 日期：2026-09-03\
> 文档状态：架构评审后定稿\
> 适用产品：寻梦环游「回响」\
> 适用能力：Live 实时语音、文字回响、正式记忆、待确认记忆、Family 查询与贡献

## 1. 设计结论

本次改造采用：

> **一个事实权威、两条回答链路、一个审核闭环。**

```text
                         唯一正式记忆权威
                      Current Formal Memory
                               |
                 +-------------+-------------+
                 |                           |
          文字回响上下文                 Live 会话投影
                 |                           |
              DeepSeek                   火山 S2S
                 |                           |
              纯文字回答                 实时语音回答
                 +-------------+-------------+
                               |
                    用户在会话中表达的新事实
                               |
                    最终回合异步、幂等持久化
                               |
                     整场关闭后 DeepSeek 整理
                               |
                         待确认记忆审核批次
                               |
                    确认 / 更正 / 丢弃（用户）
                               |
                         更新唯一正式记忆
```

模型职责不同不等于事实分叉：

- Live 使用火山端到端实时语音模型，追求低延迟、自然语音和随时打断。
- 文字回响使用 DeepSeek，追求稳定的正式记忆检索、事实引用和文字表达。
- 两者都只能读取 DreamJourney 后端授权的最新正式记忆。
- 同一事实允许不同的口语表达，但不允许姓名、学校、时间、职业、关系等事实发生差异。

## 2. 目标与非目标

### 2.1 目标

1. Live 接近自然通话：用户可连续说话、随时打断、无需等待人工恢复麦克风。
2. 移除 Live 每一轮 `ASR -> /echo/answers -> DeepSeek -> TTS` 的串行等待。
3. Live 启动时获得当前身份有权访问的正式记忆背景，并在同一会话持续使用。
4. 文字回响继续准确查询正式记忆，只显示文字，不再自动朗读。
5. Live 和文字会话新增事实都走「整理 -> 待确认 -> 用户决策 -> 正式记忆」闭环。
6. 在百级在线用户阶段保持架构轻量，不引入不必要的新数据库和检索平台。
7. 设计可扩展：未来记忆增长时，可以扩展投影、缓存或现有查询接口，而不改变事实权威。

### 2.2 非目标

本轮不做：

- 新增向量数据库、VikingDB、火山知识库或独立 RAG 平台；
- 把正式记忆托管为火山长期 Memory；
- 让火山或 DeepSeek 自动确认记忆；
- 重构数字人视频渲染；
- 重构 Publication/Visitor 全链路；
- 同时维护长期的新旧两套 Live 产品链路；
- 让文字回响播放火山或系统 TTS。

## 3. 九项架构评审决策

| 序号 | 评审问题 | 最终决策 | 开发影响 |
| --- | --- | --- | --- |
| 1 | iOS 客户端可能被抓包或篡改上下文 | 不作为当前 MVP/Pilot 的 P0 阻塞项，但服务端仍必须做身份、目标人物、权限、票据和配额校验 | 不建设复杂设备证明；绝不把跨账户授权交给客户端判断 |
| 2 | 火山是否直接使用正式记忆 | 是。Live 启动时下发预生成的只读正式记忆会话投影；会话内不逐轮检索 | 增加投影构建与缓存，火山不能写回正式记忆 |
| 3 | Family 查询范围 | Family 只能读取服务端明确授权的目标人物投影 | 增加或复用 Family 查询授权；客户端“已切换人物”不能代替授权 |
| 4 | 转写何时持久化 | 每个最终回合异步持久化，整场只整理一次 | 增加 `turnId`、`sequenceNumber`、幂等键、Outbox 和 finalize |
| 5 | Family 对话产生的事实归谁 | 默认不能直接写入目标人物记忆；属于家庭贡献，目标账户控制者审核 | 区分 Owner 自述和 Family contribution |
| 6 | 重连、撤权和会话身份 | 产品会话 ID 稳定，供应商连接 ID 可变化；重连重验权限并恢复已确认的文本历史 | 会话与连接分离，禁止跨人物热切换 |
| 7 | 文字与 Live 使用哪个模型 | Live 使用火山；文字回响使用 DeepSeek，且不朗读 | 保留 `/echo/answers` 给文字；从 Live 关键路径移除该接口 |
| 8 | 火山能力是否已被证明 | 尚未。必须先用真实账号、SDK、资源 ID 和音色完成 PoC | PoC 未通过时不得删除回滚路径或上线 |
| 9 | DFX 指标如何制定 | 借鉴火山和 OpenAI Realtime 的机制与测量维度，但使用 DreamJourney 自己的 SLO | 建立事件时间戳、打断、事实、权限、持久化和资源指标 |

## 4. 权威与数据边界

### 4.1 正式记忆权威

正式记忆是逻辑上的单一聚合，不要求数据库只能有一行：

- 可以包含多条已确认原子记忆和历史版本；
- 任一时间只能有一个当前有效的聚合投影 `projectionCheckpoint`；
- Live、文字回响、自传和其他读取方只读取这一当前投影；
- 已撤销、删除、未确认或被新版本替代的内容不得进入当前投影；
- 不允许为 Live、文字或自传分别维护事实副本。

### 4.2 三类权威

| 权威 | 组件 | 能做什么 | 不能做什么 |
| --- | --- | --- | --- |
| 事实权威 | DreamJourney 后端正式记忆 | 维护事实、版本、权限、冲突、删除和投影 | 决定实时说话节奏 |
| Live 对话权威 | 火山 S2S | 理解语音、生成回答、发声、打断、保持会话 | 创建、确认或修改正式记忆 |
| 审核权威 | Owner/目标账户控制者 | 确认、更正或丢弃 Candidate | 被模型自动替代 |

DeepSeek 是计算服务，不是权威：

- 文字回响中，它只能根据授权正式记忆组织文字。
- 会后整理中，它只能从用户最终表达中提出 Candidate。
- 它不能把助手回答、猜测或润色内容直接写成正式事实。

正式记忆写入层不做文学化或对话式润色，只做事实归纳、去重、冲突处理和结构化；温柔、友善、口语化只发生在回答生成层。

## 5. 正式记忆会话投影

### 5.1 定义

`FormalMemoryConversationSnapshot` 是由当前正式记忆聚合生成的短生命周期、只读、供应商无关视图。

它不是第二份正式记忆，也不是新的数据库主表。建议在正式记忆投影更新时同步或异步预生成，Live 启动只读取缓存结果，避免临场调用 DeepSeek 压缩。

### 5.2 建议合同

```json
{
  "schemaVersion": "formal-memory-conversation-v1",
  "subjectId": "person_xxx",
  "personaScope": "personal",
  "projectionCheckpoint": "checkpoint_xxx",
  "authorityEpoch": 42,
  "generatedAt": "2026-09-03T12:00:00Z",
  "contextHash": "sha256:...",
  "persona": {
    "displayName": "示例人物",
    "responsePerspective": "firstPerson",
    "aiDisclosureRequired": true
  },
  "coreFacts": [
    {
      "ref": "FM-001",
      "dimension": "education",
      "statement": "本科就读于 A 大学计算机专业，2016 年毕业。",
      "sourceMemoryVersionIds": ["mv_xxx"]
    }
  ],
  "dimensionSummaries": [
    {
      "dimension": "career",
      "text": "职业经历的事实性压缩摘要。",
      "supportRefs": ["FM-002", "FM-003"]
    }
  ]
}
```

### 5.3 压缩规则

记忆较长时允许压缩上下文，但只能压缩表达，不能压缩掉事实边界。

必须无损保留：

- 身份、人名、称谓和家庭关系；
- 学校、专业、职业、机构；
- 日期、时间段、地点；
- 关键事件及先后顺序；
- 用户明确表达的价值观、偏好和情绪事实；
- 尚未解决的冲突或“不确定”状态。

可以移除或合并：

- 重复表述；
- Source、Candidate 和审核过程的内部元数据；
- 无助于回答的系统字段；
- 多条事实的重复标签与模板句。

投影采用三层结构：

1. **核心事实层：** 结构化、尽量完整，不允许生成式改写改变事实。
2. **维度摘要层：** 经验、知识、情感、关系、性格等事实摘要，必须关联核心事实引用。
3. **会话历史层：** 仅当前 Live 的已完成回合，按上下文容量滚动保留。

容量阈值由 PoC 测定，不在代码中凭经验写死：

- 阈值内：下发全部核心事实和维度摘要。
- 超过阈值：先使用预生成的确定性去重和受约束摘要。
- 压缩后仍超过供应商安全容量：拒绝启动 Live 并提示使用文字回响，不能静默删除核心事实。

### 5.4 禁止下发

- 原始图片、音频和未脱敏 Source 全文；
- 未确认 Candidate；
- 已拒绝、撤销、删除或失效的记忆；
- 当前授权范围外的家庭成员数据；
- 供应商密钥、内部审计详情和其他用户标识；
- 助手此前生成但未经用户确认的推断。

## 6. 文字回响目标链路

```text
用户提交文字问题
  -> 后端根据登录态确认访问者与目标人物
  -> 读取目标人物最新正式记忆投影
  -> 按问题检索相关正式事实
  -> DeepSeek 基于事实和近期文字上下文生成回答
  -> 返回回答、memoryVersion/checkpoint、可验证引用
  -> iOS 只显示文字并结束该轮
```

硬性规则：

1. 保留 `/echo/answers` 作为文字回响正式接口，不是临时兼容接口。
2. 文字回响不得调用 `submitLiveAnswerText`、火山 TTS、系统 TTS 或数字人语音播放。
3. 文字路径不得获取 Live 音频所有权，也不能改变正在运行的 Live 状态。
4. DeepSeek 可以温柔、自然和口语化地表达，但不得修改正式事实。
5. 没有事实时明确表示不知道，可以适时邀请用户补充；不能编造。
6. 单纯询问正式记忆不产生新 Candidate。只有用户主动提供的新事实才进入会话整理。

同一正式事实允许两种模型表达不同。例如：

```text
正式事实：本科就读于 A 大学计算机专业，2016 年毕业。

DeepSeek：你是在 A 大学读的计算机专业，2016 年毕业。
火山 Live：你读的是 A 大学计算机专业，毕业是在 2016 年。
```

两者都合格；回答成其他学校、补充未记录的校园经历或声称不知道，都不合格。

## 7. Live 目标链路

### 7.1 开始会话

```text
iOS 点击 Live
  -> POST /voice/realtime-token
  -> 后端校验登录态、目标人物、Family 授权和能力开关
  -> 读取预生成 FormalMemoryConversationSnapshot
  -> 创建 productSessionId
  -> 签发绑定 user/target/purpose/checkpoint 的一次性短 TTL 票据
  -> iOS 建立火山 S2S 持续连接
  -> 一次注入人设、回答规则和正式记忆投影
  -> active/listening
```

Live 启动不能调用 DeepSeek；投影必须提前生成或以确定性方式读取。

### 7.2 会话进行中

```text
持续上行音频
  -> 火山 VAD/语义判停
  -> 火山基于当前会话和正式记忆投影生成回答
  -> 流式下行语音
  -> 用户开口触发 barge-in
  -> 当前助手输出终止
  -> 保持同一产品会话继续接收用户语音
```

会话内禁止逐轮调用 `/echo/answers`，也禁止把 DeepSeek 整段文本重新回灌火山 TTS。

会话与回合状态分离：

```text
会话：idle -> opening -> active -> reconnecting -> closing -> organizing -> terminal

active 内部：
listening -> userSpeaking -> providerThinking -> assistantSpeaking
    ^                                              |
    +-------------------- interrupted ------------+
```

一轮播放完成、TTS 结束、回答超时或用户打断，都不是产品 Live 会话结束。

### 7.3 一分钟无输入

产品规则仍为：用户主动关闭，或者连续一分钟没有用户输入才关闭。

计时规则：

- 只在真正可聆听的 `listening` 状态累计；
- 用户开始说话时重置；
- `providerThinking`、`assistantSpeaking`、重连期间暂停；
- 被打断后进入用户说话时重置；
- 助手长回答的播放时间不计入用户无输入时间。

### 7.4 回合持久化与整场整理

每个最终回合产生后，立即进入独立异步 Outbox：

```json
{
  "productSessionId": "echo_live_xxx",
  "providerSessionId": "volc_connection_xxx",
  "turnId": "turn_xxx",
  "sequenceNumber": 7,
  "role": "user",
  "text": "最终转写",
  "final": true,
  "interrupted": false,
  "occurredAt": "...",
  "idempotencyKey": "echo_live_xxx:7:turn_xxx"
}
```

约束：

- partial 转写不持久化为事实；
- 网络请求和重试不能阻塞音频上行、模型回复或打断；
- 后端按 `productSessionId + sequenceNumber + turnId` 去重；
- 断网时写入短期本地 Outbox，恢复后按顺序补传；
- 助手回合可以保存为上下文，但不能作为事实证据；
- 会话关闭只发送一次幂等 `finalize`；
- `finalize` 后把整场建立为一个 Source，并最多产生一个审核批次；
- 无新增用户事实时允许零 Candidate。

这不是“一问一答生成一次记忆”。逐回合持久化解决可靠性，整场 finalize 才触发一次整理。

## 8. Family 权限与记忆归属

### 8.1 查询权限

Family 查询必须由后端判断：

```text
当前登录者
  + 目标人物
  + 有效家庭关系
  + 有效 echo.query 授权范围
  + 未撤销/未过期状态
  -> 可读取该目标人物的授权正式记忆投影
```

不能用以下信息代替授权：

- iOS 当前显示的家人名字；
- 客户端传来的 `personaScope=family`；
- 仅存在通讯录或邀请记录；
- 用户知道目标人物 ID。

人物切换必须关闭旧 Live，重新申请票据、重新鉴权并载入新投影，禁止热切换上下文。

### 8.2 新事实归属

| 场景 | 默认归属 | 审核人 |
| --- | --- | --- |
| Owner 与自己的 AI 对话并讲述自己的事实 | Owner 的待确认记忆 | Owner |
| Family 与目标人物数字人对话并补充目标人物故事 | Family contribution | 目标账户控制者 |
| Family 在对话中讲述自己的个人事实 | 默认不自动写入任何一方 | 需要明确选择后进入自己的待确认记忆 |
| 助手生成或推断的内容 | 不得成为事实 | 无 |

“用第一人称扮演家人”只影响回答视角，不改变记忆所有权，也不表示 AI 就是本人。界面仍需保留“AI 生成，非真人本人”披露。

## 9. 重连、撤权和会话恢复

### 9.1 标识模型

- `productSessionId`：一次用户打开到关闭的产品 Live，重连后保持不变。
- `providerSessionId`：一次火山连接，每次重连生成新值。
- `turnId`：一个最终用户或助手回合。
- `sequenceNumber`：产品会话内严格递增。
- `idempotencyKey`：保证重试不重复写入。

### 9.2 重连流程

1. 暂停一分钟无输入计时。
2. 结束旧 `providerSessionId`，保留 `productSessionId`。
3. 后端重新验证登录状态、目标人物和 Family 授权。
4. 使用原 `projectionCheckpoint` 恢复同一会话；不能在重连时悄悄换人物或事实版本。
5. 只回放已经持久化的最终文本历史，不回放音频和 partial。
6. 恢复成功后重新进入 `listening`。
7. 超过配置的重试次数或授权失效时，关闭会话并对已落地回合执行可选择的整理。

新一轮产品 Live 才使用最新正式记忆 checkpoint。

## 10. 安全决策

用户正常使用 iOS 时，TLS/WSS 可以防止普通链路窃听。设备所有者主动安装根证书、越狱 Hook 或使用修改版客户端的风险不作为当前百级用户 Pilot 的 P0 阻塞项。

但以下服务端边界仍不可省略：

1. 永久供应商密钥只能在后端。
2. 一次性票据绑定登录用户、目标人物、用途、checkpoint、短 TTL 和单次消费。
3. 代理建立连接时再次验证票据与登录会话。
4. Family/Visitor 的跨身份访问必须由后端授权，不信任客户端参数。
5. 限制并发会话、单帧大小、会话总流量和最长会话时间。
6. 日志只记录 hash、版本、时延和状态，不记录完整正式记忆与音频正文。

后续扩大公测、接入高敏感人物或商业化前，再升级设备完整性、证书固定、反重放和威胁模型；这些不是本轮阻塞项。

## 11. 性能设计

### 11.1 实时关键路径

实时关键路径只包含：

```text
音频上行 -> 火山 S2S -> 音频下行
```

以下全部移出关键路径：

- `/echo/answers`；
- DeepSeek；
- 正式记忆逐轮搜索；
- Candidate 整理；
- 回合持久化等待；
- 引用展示的异步计算。

### 11.2 持久化性能门槛

逐回合持久化采用独立串行队列或 actor，不等待网络结果即可继续下一轮。

与关闭持久化的基线相比：

- P95“用户说完到首个回复音频”增幅不超过 10%；
- P95“用户插话到助手停止”增幅不超过 10%；
- CPU、网络流量、电量消耗任一增幅不超过 20%；
- 不新增卡顿、首字丢失、重复回合或被动结束。

这些是发布门禁，不是未经测试的理论保证。

## 12. DFX 指标

### 12.1 延迟与连续性

| 指标 | 验收目标 |
| --- | --- |
| 点击 Live 到可说话 | P50 <= 1.2 秒，P95 <= 2.0 秒 |
| 用户自然停顿到首个回复音频 | P50 <= 1.5 秒，P95 <= 2.2 秒 |
| 用户插话到助手声音停止 | P50 <= 180 ms，P95 <= 300 ms |
| 打断后用户语音重新被接纳 | P95 <= 300 ms |
| 连续 20 轮 | 0 次被动结束，0 次卡在“正在回响” |
| 长回答结束后立即开口 | 不丢首句，无额外恢复窗口 |

火山提供可配置判停窗口与打断能力，但具体阈值必须在真实 iPhone、真实账号和当前网络代理上测试，不能直接把供应商宣传值当作产品 SLO。

## 13. 发布策略

第一步只批准 PoC，不直接替换生产：

1. 证明当前火山账号、SDK、资源 ID 和目标音色支持持续 S2S、正式记忆上下文和打断。
2. 完成后端投影和票据绑定。
3. 完成 Owner Live 单人链路。
4. 完成异步回合持久化、重连和整场 finalize。
5. 完成文字回响纯文字化。
6. 完成 Family 查询与贡献审核。
7. 完成自动化、真机、弱网、权限和性能验收。

保留一个短期服务端开关：

```text
ECHO_LIVE_PROVIDER_DIALOG_ENABLED
```

- 关闭：当前 Live 级联链路，仅用于回滚和 A/B 基线。
- 开启：火山 S2S Live。

项目尚未发布，不需要长期兼容旧版。新链路通过门禁后，应删除旧 Live 的逐轮 `/echo/answers -> submitLiveAnswerText` 实现及其专用状态分支；`/echo/answers` 本身必须保留给文字回响。

## 14. 架构批准条件

满足以下条件后，架构可从“PoC 批准”进入“实现批准”：

1. 火山能在一个持续会话中读取正式记忆投影并正确回答黄金事实。
2. 真实 iPhone 上打断和连续聆听达到 DFX 指标。
3. 投影容量、模型版本和复刻音色组合已经实测，不依赖猜测。
4. 最终回合持久化对实时链路的延迟回归 <= 10%，资源回归 <= 20%。
5. Family 权限与贡献归属已由服务端自动化测试证明。
6. 文字回响不朗读，同时继续基于最新正式记忆正确回答。
7. 整场会话只整理一次，用户确认前不更新正式记忆。
