## 1. 文档目的

本文档定义寻梦环游个人记忆库与数字分身平台的产品目标、用户角色、业务边界、功能需求、权限规则、验收标准和阶段规划，作为产品、iOS、后端、算法、测试、运营与合规评审的共同依据。

本文档聚焦当前可落地的第一版后端能力：

```text
本人通过文字、实时语音和资料上传持续输入
→ 系统形成可追溯的私人记忆库
→ 本人基于私人记忆库问答
→ 本人主动审核和发布部分内容
→ 他人通过文字或实时语音与“数字分身”对话
```

## 2. 产品定义

### 2.1 一句话定义

寻梦环游是一个由用户持续建设、由 AI 协助整理、由用户决定公开范围的个人记忆与数字分身平台。

### 2.2 产品要解决的问题

用户的记忆、情绪、知识、经验和人际关系长期散落在聊天、语音、照片、文件和脑海中，存在以下问题：

- 内容碎片化，难以持续整理。
- 传统网盘和笔记只能保存，不能理解和调用。
- 通用 AI 缺少用户长期上下文，回答容易泛化。
- AI 自动总结可能误解用户，且难以追溯来源。
- 私人内容与可分享内容边界不清，存在隐私风险。
- 人的知识和经验很难以可交互的方式分享给家人或他人。

### 2.3 核心产品形态

产品由两个相互隔离的知识域组成：

| 知识域 | 使用者 | 内容来源 | 主要用途 |
| --- | --- | --- | --- |
| 私人知识域 | 本人 | 本人对话、上传资料、本人确认的记忆 | 记录、复盘、私人问答、持续建库 |
| 公开人格知识域 | 被授权访问者 | 本人明确发布的内容副本 | 与数字分身对话、获取本人授权的知识与经验 |

公开人格知识域不是私人知识域的筛选视图，而是本人确认后生成的独立发布副本。撤回发布后，公开副本及其索引必须失效。

### 2.4 核心价值

- 对本人：获得一个可持续积累、可追溯、能理解长期上下文的个人外脑。
- 对家人和朋友：在授权范围内了解用户的经历、观点、故事和经验。
- 对知识访问者：通过对话方式获取用户公开分享的专业知识和决策经验。
- 对平台：沉淀可信的长期记忆处理、权限治理和数字人格生成能力。

## 3. 产品原则

1. 原始证据优先于 AI 总结。
2. 私人内容默认不公开。
3. 公开必须由本人主动完成，不采用默认勾选。
4. AI 可以提出候选记忆，不能静默定义一个人。
5. 事实、主观感受和 AI 推断必须区分。
6. 关系与情绪具有时间和视角，不能被写成永久客观结论。
7. 所有重要回答应能追溯到记忆或原始资料。
8. 没有足够证据时，数字分身应明确表示不知道。
9. 权限控制由后端确定性逻辑执行，不能依赖提示词约束。
10. 用户拥有导出、纠正、撤回和删除个人数据的能力。

## 4. 产品目标与非目标

### 4.1 MVP 产品目标

- 支持现有 iOS App 接入统一后端。
- 支持用户通过文字对话和资料上传持续建设私人知识库。
- 支持本人完成声音授权采集、声音克隆和实时双向语音对话。
- 支持从内容中提取候选记忆、情绪、知识、经验、人物和关系。
- 支持用户审核、修正、确认或拒绝候选内容。
- 支持本人基于私人知识库进行有来源的问答。
- 支持本人将选定内容发布到独立的公开人格知识域。
- 支持他人通过分享页面与数字分身对话。
- 支持账号隔离、访问控制、审计、导出和删除。
- 在百级用户阶段保持低运维成本和可持续演进能力。

### 4.2 MVP 非目标

- 不开发新的 Web 或跨平台用户端替代现有 iOS App。
- 不做完整 Obsidian 或笔记编辑器。
- 不做视频内容理解；视频可以保存，内容理解列为后续低优先级。
- 不做第三方声音克隆；MVP 只支持资产拥有者在明确授权后克隆本人的声音。
- 不提供任意文本配音、音频下载或面向外部的通用声音生成接口。
- 不做复杂家庭群组和多层继承权限。
- 不做付费 API 市场及自动收益分配。
- 不做医疗诊断、心理诊断或治疗建议。
- 不做未经本人授权的“真人复刻”或已故人物自动复现。
- 不做大模型微调平台。
- 不以关系图谱视觉效果作为 MVP 的核心验收目标。

## 5. 用户角色

| 角色 | 定义 | MVP 权限 |
| --- | --- | --- |
| 资产拥有者 Owner | 建设并拥有个人知识库的注册用户 | 上传、对话、审核、查询、发布、撤回、导出、删除 |
| 访问者 Visitor | 通过分享入口与数字分身对话的人 | 仅访问公开人格知识域，不可写入私人知识域 |
| 平台运营 Operator | 处理用户反馈、任务异常和运营配置的内部人员 | 仅访问必要的元数据，不默认查看私人正文 |
| 平台管理员 Admin | 维护系统配置、权限和安全事件的授权人员 | 受审计的最小必要权限 |

后续角色包括家庭成员、资料贡献者、继承人、专业服务人员和商业 API 调用方，均不进入本次 MVP。

## 6. 核心概念

### 6.1 数字人格 Persona

由某个用户拥有和管理的数字身份。MVP 默认一个用户拥有一个数字人格，但数据模型允许未来扩展多个数字人格。

### 6.2 原始资料 Source

用户主动输入或上传的原始内容，包括：

- 对话消息
- 纯文本
- PDF、DOCX 等文档
- 图片及 OCR 文本
- 音频及转写文本
- 实时语音对话的最终转写文本

原始资料是后续记忆提取和回答引用的证据，不应被 AI 生成内容覆盖。

### 6.3 记忆条目 Memory Item

系统从原始资料中提取，或由用户直接创建的一条可独立理解、可检索、可修正的内容。

MVP 支持以下类型：

| 类型 | 说明 | 示例 |
| --- | --- | --- |
| `event` | 有时间背景的经历或事件 | 2024 年第一次创业失败 |
| `fact` | 关于本人的事实性信息 | 曾在上海工作五年 |
| `emotion_observation` | 特定时刻的情绪观察 | 汇报前感到明显焦虑 |
| `relationship_observation` | 从本人视角记录的关系状态 | 最近与父亲沟通有所缓和 |
| `knowledge` | 本人掌握或收藏的知识 | 对现金流管理的理解 |
| `experience` | 背景、行动、结果与反思 | 一次招聘失败的复盘 |
| `value_or_preference` | 价值观、偏好或边界 | 更看重生活平衡而非短期收入 |
| `story` | 适合叙述和分享的人生故事 | 童年搬家的经历 |

### 6.4 候选记忆 Memory Candidate

AI 从对话或资料中提取但尚未被用户确认的记忆条目。候选记忆不能直接进入公开人格知识域。

### 6.5 实体 Entity

记忆中出现的人物、地点、组织、项目和主题。

### 6.6 关系 Relation

实体之间带有类型、时间、视角和证据的连接。例如家庭关系、朋友关系、合作关系、参与关系和知识关联。

### 6.7 发布内容 Publication

用户从私人记忆中选择并确认发布的内容快照。发布内容可以经过脱敏、改写或概括，并与私人原文保持可追溯关联。

### 6.8 声音档案 Voice Profile

由资产拥有者主动录制、授权并确认启用的声音档案，包括授权记录、声音样本、克隆模型标识、质量状态和允许使用范围。

私人语音回答与公开数字分身使用克隆声音是两项独立授权。用户可以只在本人会话中使用克隆声音，而不允许访问者听到该声音。

### 6.9 实时语音会话 Realtime Voice Session

用户或访问者通过麦克风与 AI 进行的双向流式语音会话。系统实时完成语音识别、知识检索、回答生成和语音合成，并支持用户在 AI 播放期间打断。

## 7. 核心用户旅程

### 7.1 首次建库

```text
用户登录 iOS App
→ 创建或初始化数字人格
→ 输入一段自我介绍或上传第一份资料
→ 系统处理并生成候选记忆
→ 用户审核候选记忆
→ 私人知识库形成首批可查询内容
```

### 7.2 日常对话持续建库

```text
用户与 AI 对话或讲述一件事
→ 原始消息立即保存
→ AI 正常回应
→ 后台异步提取候选记忆
→ 用户在“记忆待确认”中审核
→ 确认内容进入私人知识库
```

### 7.3 本人知识问答

```text
用户提问
→ 系统检索私人记忆、知识、人物关系和原始来源
→ AI 基于检索证据回答
→ iOS 流式展示回答及来源
→ 用户可以纠正答案或对应记忆
```

### 7.4 发布数字分身内容

```text
用户选择一条或多条私人记忆
→ 系统生成建议公开摘要
→ 用户检查敏感信息和表述
→ 用户确认发布
→ 系统建立独立公开副本和公开索引
```

### 7.5 他人与数字分身对话

```text
访问者打开分享入口
→ 页面明确提示这是 AI 数字人格
→ 访问者提问
→ 系统只检索公开人格知识域
→ 数字分身基于授权内容回答
→ 资料不足时明确表示不知道
```

### 7.6 声音建档与实时语音

```text
本人阅读声音克隆授权说明
→ 按随机提示录制本人声音和授权语句
→ 系统校验音质、时长和活体一致性
→ 后台异步创建声音档案
→ 本人试听并确认启用
→ 本人通过实时语音与私人助手对话
→ 本人可另行授权数字分身对访问者使用克隆声音
→ 用户讲话时可以打断 AI 播放
```

## 8. 功能需求

优先级说明：`P0` 为 MVP 上线阻断项，`P1` 为首轮迭代应完成项，`P2` 为后续增强项。

### 8.1 账号与数字人格

#### FR-ACC-001 用户身份接入（P0）

后端应兼容现有 iOS App 的用户身份体系；若现有体系不完整，至少支持 Sign in with Apple 或手机号方案中的一种。

验收标准：

- 后端能够验证用户身份并签发或接受有效访问凭证。
- 用户只能访问自己的私人知识域。
- 凭证过期、撤销和刷新有明确处理。
- 关键鉴权失败写入安全日志，但日志不记录完整令牌。

#### FR-ACC-002 数字人格初始化（P0）

首次使用时为用户创建数字人格，包含显示名称、头像、简介、语言偏好和默认回答风格。

验收标准：

- 一个用户在 MVP 阶段最多拥有一个有效数字人格。
- 数字人格默认状态为私人。
- 未完成公开设置前，不生成可被访问的公开入口。

### 8.2 资料上传与处理

#### FR-SRC-001 文件直传（P0）

iOS App 应通过后端获取短期有效的预签名地址，并将文件直接上传到对象存储。

验收标准：

- 后端不承担大文件内容中转。
- 上传地址绑定用户、文件类型、文件大小和过期时间。
- 上传完成后可创建对应原始资料记录。
- 不支持的文件类型和超限文件被拒绝，并返回可展示错误。

#### FR-SRC-002 MVP 文件类型（P0）

MVP 支持文本、PDF、DOCX、常见图片格式和常见音频格式。视频只保存原文件，不进行内容理解。

验收标准：

- 文本和文档可提取正文。
- 图片可进入 OCR 流程。
- 音频可进入转写流程。
- 处理状态至少包括：待处理、处理中、待审核、完成、失败。
- 文件限制由服务端配置，不写死在 iOS App。

#### FR-SRC-003 原始资料保留（P0）

系统必须保留原始文件、原始文本或原始对话，以及处理版本和来源信息。

验收标准：

- AI 摘要不会覆盖原始资料。
- 每条派生记忆可以追溯到一个或多个原始来源片段。
- 用户删除原始资料时，系统提示其对派生记忆和公开内容的影响。

### 8.3 对话与持续建库

#### FR-CHAT-001 本人文字对话（P0）

iOS App 可创建本人会话并以流式方式接收 AI 回复。

验收标准：

- 用户消息先持久化，再触发模型回答。
- 网络中断后可重新获取已保存消息。
- 模型回复中断时保留失败状态，允许重试。
- 对话记录默认仅本人可见。

#### FR-CHAT-002 对话记忆提取（P0）

系统应从有长期价值的对话中异步提取候选记忆，而不是把全部对话都直接写成记忆。

验收标准：

- 候选记忆包含类型、内容、来源消息、置信度和敏感等级。
- 闲聊、重复内容和低信息内容可以不生成候选记忆。
- 提取失败不影响当前对话，并可以重试。
- 模型与提示词版本可追踪。

#### FR-CHAT-003 风险分级确认（P0）

系统根据内容敏感度决定确认方式。

| 风险级别 | 示例 | MVP 处理 |
| --- | --- | --- |
| 低 | 普通知识、事件标题、主题标签 | 进入待确认列表，可批量确认 |
| 中 | 偏好、经验结论、人物关系变化 | 必须由用户确认或修改 |
| 高 | 健康、财务、家庭冲突、未成年人、强烈负面评价 | 明确提示敏感性，逐条确认，默认永不公开 |

### 8.4 声音克隆与实时语音

#### FR-VOICE-001 本人声音采集与授权（P0）

资产拥有者可以通过 iOS App 录制本人的声音样本，并在提交前完成声音克隆专项授权。

验收标准：

- 录制前展示声音用途、保存位置、公开范围、撤回和删除方式。
- 用户需要录制随机授权语句，确认声音属于本人并授权平台处理。
- 服务端校验样本格式、时长、信噪比、重复提交和基础活体一致性。
- 不满足质量要求时返回明确的补录建议。
- 声音样本默认最高敏感级别，不参与记忆提取，不进入公开知识域。
- MVP 不允许上传或克隆其他自然人的声音。

#### FR-VOICE-002 声音档案创建与生命周期（P0）

系统应异步创建声音档案，并支持预览、启用、暂停、重新录制和删除。

验收标准：

- 声音档案状态至少包括：待授权、采集中、校验中、训练中、待试听、已启用、已暂停、失败、删除中、已删除。
- 训练完成后必须由本人试听确认，不能自动启用。
- 同一数字人格在 MVP 阶段最多有一个处于启用状态的克隆声音。
- 声音供应商标识、模型版本、样本版本和授权版本可追踪。
- 用户删除声音档案时，同时删除本地样本、模型引用和供应商侧可删除资产。
- 系统不得向用户或访问者暴露可复用的供应商声音模型标识。

#### FR-VOICE-003 本人实时语音对话（P0）

Owner 可以通过 iOS App 与私人助手进行双向实时语音对话，并使用本人已启用的克隆声音播放 AI 回答。

验收标准：

- 会话建立后支持持续上传麦克风音频和流式返回合成音频。
- iOS 可展示语音识别的临时文本和最终文本。
- 用户开始讲话时能够中断正在生成或播放的 AI 回答。
- 每个完整语音轮次保存最终转写、最终回答和来源引用，临时识别结果不进入记忆库。
- 最终转写可以触发与文字对话相同的候选记忆提取流程。
- 声音克隆不可用时可降级到系统默认声音或文字回答，并明确告知用户。
- 网络中断后可以结束当前轮次并恢复会话历史，不要求无缝续传丢失的音频帧。

#### FR-VOICE-004 访问者实时语音对话（P0）

Visitor 可以在公开数字分身入口进行实时语音对话。只有 Owner 单独授权公开声音后，系统才能使用克隆声音向访问者播放回答。

验收标准：

- Visitor 实时语音问答只检索公开人格知识域。
- 页面和语音会话开始前明确提示当前声音为 AI 合成声音。
- 未取得公开声音授权、授权被撤回或声音档案不可用时，使用默认声音或仅返回文字。
- Visitor 不能下载声音样本、模型或单独生成任意文本配音。
- Visitor 的音频和转写不能进入 Owner 的私人知识库。
- 公开语音会话执行与文字访问相同的限流、禁止主题和高风险内容策略。

#### FR-VOICE-005 语音留存与撤回（P0）

实时语音默认只保存最终转写和必要的会话元数据，不长期保存连续原始录音。因质量分析或用户主动保存需要保留录音时，必须单独告知并取得授权。

验收标准：

- Owner 可以分别关闭私人克隆声音和公开克隆声音。
- 公开声音授权撤回后，新会话立即停止使用克隆声音。
- 声音样本和生成音频不出现在普通数据导出之外的公开下载入口。
- 生成音频在供应商支持时添加来源标识或水印，并保留生成审计记录。
- 声音相关删除任务可追踪、可重试并展示最终状态。

### 8.5 记忆审核与管理

#### FR-MEM-001 候选记忆审核（P0）

用户可以查看、修改、确认、拒绝候选记忆，并调整时间、类型、敏感度和关联人物。

验收标准：

- 候选记忆不经确认不得进入公开知识域。
- 拒绝的候选记忆保留必要的审核记录，但不参与问答检索。
- 用户修改后的内容标记为用户确认版本。
- 每次操作记录操作者和时间。

#### FR-MEM-002 记忆版本与纠正（P0）

用户纠正正式记忆时，系统建立新版本，并保留旧版本的替代关系。

验收标准：

- 旧版本不再参与默认检索。
- 可以查看记忆的来源与修改历史。
- 与旧版本关联的公开内容被标记为需要重新确认。

#### FR-MEM-003 冲突提示（P1）

当新记忆与已有记忆在关键事实、时间或关系状态上明显冲突时，系统应提示用户确认，而不是自行覆盖。

#### FR-MEM-004 人物与关系管理（P1）

用户可以合并重复人物、修改人物称谓，并查看与该人物关联的事件和关系观察。

验收标准：

- 关系条目包含时间范围、本人视角和来源证据。
- 人物关系默认仅本人可见。
- 合并人物后，相关记忆和关系不丢失。

### 8.6 本人检索与问答

#### FR-QA-001 私人知识问答（P0）

用户可以针对自己的经历、情绪、知识、经验和关系进行提问。

验收标准：

- 检索范围仅限当前用户的私人知识域。
- 回答基于全文、语义、时间、类型和实体关系的组合检索。
- 事实性回答提供可点击的记忆来源。
- 证据不足时明确说明记录不足，不补造个人经历。
- 用户可以对回答标记准确、不准确或无帮助。

#### FR-QA-002 回答纠错（P1）

用户指出回答错误时，系统应允许定位错误来源并生成待确认的记忆修正，而不是只调整当前会话措辞。

### 8.7 内容发布

#### FR-PUB-001 私人内容发布（P0）

用户可以选择一条或多条已确认记忆，生成公开摘要并主动发布。

验收标准：

- 发布前展示最终公开文本、关联主题和可能暴露的人物信息。
- 默认不公开原始文件、完整对话和私人附件。
- 每次发布生成不可变的版本快照。
- 发布操作具有二次确认。

#### FR-PUB-002 发布撤回（P0）

用户可以随时撤回公开内容。

验收标准：

- 撤回后公开索引立即停止返回该内容。
- 新的数字分身回答不能再引用已撤回内容。
- 已产生的历史会话按隐私政策处理，并记录撤回时间。

#### FR-PUB-003 公开人格配置（P0）

用户可以设置公开名称、头像、简介、公开回答风格、允许讨论的主题和禁止讨论的主题。

公开人格页面必须明确说明：

- 当前对象是由 AI 生成的数字人格，不是真人实时回复。
- 回答依据是本人主动授权的资料。
- 回答可能存在误差，重要信息应另行核实。

### 8.8 访问者数字分身对话

#### FR-VIS-001 公开对话入口（P0）

访问者可以通过分享链接进入数字分身对话。MVP 可允许匿名访问，但必须启用访问频控和滥用防护。

验收标准：

- 公开入口只能读取公开人格知识域。
- 访问者身份不能切换为 Owner 权限。
- 访问者提示词不能改变后端检索范围。
- 公开入口支持被用户暂停或关闭。

#### FR-VIS-002 基于授权资料回答（P0）

数字分身回答必须以本人发布内容为事实来源。

验收标准：

- 没有公开依据时回答“不知道”或说明尚未分享。
- 不引用私人资料的标题、路径、人物或内容。
- 不把通用模型知识表述为本人的经历或观点。
- 回答可以提供经过脱敏的来源标签，例如“来自本人授权的 2022 年创业复盘”。

#### FR-VIS-003 访问者反馈（P1）

访问者可以举报不准确、不适当或可能侵犯隐私的回答。反馈进入平台审核和 Owner 可见的待处理区，但不能直接修改数字人格。

### 8.9 数据权利与隐私

#### FR-PRIV-001 数据隔离（P0）

所有用户数据必须按用户和数字人格隔离，任何跨用户读取均应由明确的公开发布或授权记录支持。

#### FR-PRIV-002 敏感内容（P0）

系统至少支持以下敏感等级：

```text
private
sensitive
never_share
publishable
published
```

`never_share` 内容不得进入公开候选、公开索引或公开回答上下文。

#### FR-PRIV-003 第三方人物信息（P0）

用户记录的家庭关系和社会关系默认属于私人内容。涉及第三方的健康、财务、身份、联系方式、未成年人和负面评价，不得被系统自动建议公开。

#### FR-PRIV-004 数据导出（P0）

用户可以导出自己的原始资料清单、记忆、实体、关系和发布记录。结构化数据至少支持 JSON，阅读型数据支持 Markdown。用户可以申请导出本人上传的原始声音样本，但供应商侧克隆模型和内部模型标识不属于可导出文件。

#### FR-PRIV-005 数据删除（P0）

用户可以删除单条资料、单条记忆、全部公开内容或整个账号。

验收标准：

- 删除流程说明影响范围和不可恢复性。
- 账号删除覆盖数据库、对象存储、向量索引、公开副本、声音样本和供应商侧可删除的克隆声音资产。
- 法律或安全要求保留的最小审计记录应脱敏保存，并在隐私政策中说明。

#### FR-PRIV-006 声音数据保护（P0）

声音样本、授权录音、克隆模型标识和声音特征数据按最高敏感等级处理。

验收标准：

- 声音相关资产与普通资料分开标识、授权和审计。
- 内部运营人员默认不能试听或下载用户声音样本。
- 声音样本不能用于模型训练、产品改进或其他用途，除非用户另行明确授权。
- 私人声音授权不自动包含公开声音授权。
- 所有供应商调用使用完成当前任务所需的最小声音数据。

### 8.10 安全与危机内容

#### FR-SAFE-001 高风险表达处理（P0）

当本人或访问者出现明确的自伤、伤人或现实危机表达时，系统应退出人格模拟式回答，提供明确的现实求助建议和适用地区的紧急资源。

系统不得：

- 声称完成医学或心理诊断。
- 将情绪趋势包装成疾病结论。
- 鼓励用户用数字分身替代现实关系或专业帮助。

#### FR-SAFE-002 滥用防护（P0）

公开对话接口必须支持按 IP、设备、会话和数字人格的限流，并能封禁明显的抓取、提示注入和攻击行为。

### 8.11 运营与审计

#### FR-OPS-001 任务状态（P0）

运营人员可以查看资料处理任务的状态、耗时、失败原因和重试次数，但默认不能查看完整私人正文。

#### FR-OPS-002 模型调用审计（P0）

系统记录模型供应商、模型标识、用途、提示词版本、Token 用量、延迟、成功状态和关联业务对象。

#### FR-OPS-003 权限审计（P0）

发布、撤回、导出、删除、管理员访问和权限变更必须写入不可由普通用户修改的审计日志。

## 9. 权限模型

### 9.1 MVP 可见性

| 可见性 | 本人可见 | 访问者可见 | 可用于数字分身 |
| --- | --- | --- | --- |
| 私人 | 是 | 否 | 否 |
| 高敏 | 是 | 否 | 否 |
| 永不分享 | 是 | 否 | 否 |
| 待发布 | 是 | 否 | 否 |
| 已发布副本 | 是 | 是 | 是 |

### 9.2 权限强制原则

- iOS 传入的 `user_id`、`persona_id` 和权限声明均不能直接信任。
- 后端必须根据认证身份重新确认资源归属。
- 公开问答代码路径不得连接私人检索函数。
- 管理员临时访问敏感内容必须有原因、时效和审计记录。
- Prompt 中的安全规则只能作为补充，不能代替数据访问控制。

### 9.3 声音授权范围

| 授权状态 | 本人私人会话 | 访问者公开会话 | 任意文本配音/下载 |
| --- | --- | --- | --- |
| 未授权 | 不可使用 | 不可使用 | 不可使用 |
| 私人声音已授权 | 可使用 | 不可使用 | 不可使用 |
| 公开声音已授权 | 可使用 | 可使用 | 不可使用 |
| 已暂停或已撤回 | 不可在新会话中使用 | 不可使用 | 不可使用 |

公开声音授权必须以当前有效的私人声音授权和声音档案为前提；私人授权撤回时，公开授权同时失效。

## 10. AI 行为要求

### 10.1 记忆提取

- 使用结构化输出生成候选记忆。
- 每条候选记忆关联来源片段。
- 区分明确事实、本人陈述、情绪观察和模型推断。
- 不因一次事件直接生成稳定人格结论。
- 重复或高度相似内容优先合并提示，不重复堆积。

### 10.2 本人回答

- 优先使用用户确认的记忆。
- 候选记忆默认不作为确定事实引用。
- 回答中区分“记录显示”和“系统推测”。
- 允许总结趋势，但必须说明样本和不确定性。

### 10.3 数字分身回答

- 事实内容仅来自已发布副本。
- 表达风格可以来自用户配置，但不能突破内容权限。
- 不代替本人作出现实承诺、交易决定或关系表态。
- 不回答被 Owner 禁止的主题。
- 不冒充真人在线，也不暗示拥有意识或实时感受。

### 10.4 实时语音回答

- 语音和文字回答使用相同的知识域、权限、来源和禁止主题规则。
- 临时语音识别结果不得直接成为长期记忆，只有最终转写可以进入候选记忆流程。
- 用户打断 AI 时，应停止继续生成和播放被打断的回答。
- 数字分身使用克隆声音时，界面必须持续提供 AI 合成声音标识。
- 系统不得使用克隆声音生成超出当前对话场景的任意内容或可下载音频。

## 11. 非功能需求

### 11.1 性能目标

| 指标 | MVP 目标 |
| --- | --- |
| 注册用户规模 | 100-500 |
| 同时在线用户 | 50-200 |
| 同时实时语音会话 | 10-20 |
| 普通 API P95 | 小于 500 ms，不含第三方模型和文件处理 |
| 文字对话首字响应 P95 | 小于 4 秒 |
| 完整问答 P95 | 小于 15 秒 |
| 实时语音连接建立 P95 | 小于 2 秒 |
| 用户结束讲话到首段回答音频 P95 | 小于 3 秒 |
| 用户打断到停止播放 P95 | 小于 800 ms |
| 实时语音会话成功率 | 大于 98%，不含用户主动断网 |
| 文件上传成功率 | 大于 99% |
| 异步任务状态可查询率 | 100% |
| 多用户数据串扰 | 0 容忍 |
| 私人内容公开泄漏 | 0 容忍 |

### 11.2 可用性

- API 和任务处理相互隔离，文件解析失败不影响对话。
- 所有异步任务支持超时、有限重试和失败可见。
- 模型服务不可用时返回明确的可重试状态。
- 数据库执行每日备份，并定期验证恢复流程。

### 11.3 可维护性

- 后端采用模块化单体，不在 MVP 拆分微服务。
- AI 供应商通过统一接口接入，业务逻辑不依赖单一模型。
- Prompt 和结构化输出 Schema 版本化。
- 数据库变更通过迁移管理。
- API 使用 `/v1` 版本前缀并保持向后兼容策略。

### 11.4 安全性

- 全链路 HTTPS。
- 对象存储默认私有，使用短期签名地址。
- 密钥不进入代码、客户端和普通日志。
- 高权限操作采用最小权限和完整审计。
- 日志默认脱敏，不记录原始令牌、完整 Prompt 或私人正文。
- 上传文件进行类型、大小、内容签名和解析超时限制。

## 12. 关键状态

### 12.1 原始资料状态

```text
uploaded → queued → processing → review_ready → completed
                              ↘ failed → queued（重试）
```

### 12.2 记忆状态

```text
candidate → confirmed → superseded
         ↘ rejected
confirmed → deleted
```

### 12.3 发布状态

```text
draft → published → withdrawn
                 ↘ suspended
```

### 12.4 声音档案状态

```text
pending_consent → collecting → validating → training → preview_ready → active
                                  ↘ failed             ↘ rejected
active → paused → active
active / paused / failed → deleting → deleted
```

### 12.5 实时语音会话状态

```text
created → connecting → active → completed
                 ↘ failed
active → interrupted → active
active → disconnected → completed / failed
```

## 14. MVP 范围与阶段规划

### 14.1 M0：后端闭环验证

- 用户身份验证。
- 文本输入和原始消息保存。
- 候选记忆提取。
- 用户确认记忆。
- 私人知识问答及来源引用。
- 本人声音授权录制、声音克隆和试听确认链路。
- 至少跑通一个支持打断的实时双向语音对话闭环。

### 14.2 M1：百级用户 MVP

- 文件直传和异步解析。
- 文档、图片 OCR 和音频转写。
- 声音样本质量校验、声音档案生命周期和专项授权。
- Owner 使用克隆声音进行实时语音对话。
- Visitor 在公开授权下使用克隆声音进行实时语音对话。
- 语音打断、默认声音降级、会话转写和成本统计。
- 记忆版本、人物和关系。
- 私人/公开双知识域。
- 发布、撤回和数字分身公开对话。
- 限流、审计、导出和删除。
- 模型成本统计和基础运营工具。

### 14.3 M2：产品增强

- 家庭成员与受邀访问。
- 更细粒度的主题和人群授权。
- 时间线、人物关系图和情绪趋势。
- 多语言、语气控制、降噪和声音自然度优化。
- 视频内容理解评估，保持低优先级。
- 多模型路由、缓存和更精细的检索评估。

### 14.4 M3：数字传承

- 继承人和授权链。
- 生前/身后状态及封存流程。
- 长期托管、数字遗嘱和商业授权。
- 声音、肖像和知识产权授权管理。

## 15. 上线验收门槛

MVP 上线前必须满足：

- 核心 P0 需求全部通过验收。
- Owner 与 Visitor 权限路径完成自动化隔离测试。
- 使用提示注入测试无法访问私人知识域。
- 删除账号后，数据库、对象存储和公开索引完成一致删除验证。
- 至少完成一轮真实用户资料的提取质量评估。
- 公开回答能够稳定拒绝无依据问题。
- 文件解析失败、模型超时、网络中断和任务重试均有明确状态。
- 声音采集、专项授权、试听确认、暂停、公开授权和删除流程全部通过验收。
- 未取得公开声音授权时，Visitor 无法使用克隆声音。
- 声音授权撤回后，新会话立即停止使用克隆声音。
- 声音删除能够覆盖对象存储和供应商侧可删除资产，并展示最终状态。
- 实时语音完成连接、识别、检索、回答、合成、播放和用户打断的端到端测试。
- 实时语音在弱网、断网、模型超时和声音合成失败时具备明确降级行为。
- 访问者不能使用克隆声音生成任意文本配音或下载可复用音频资产。
- 隐私政策、用户协议、AI 标识和数据授权文本经过合规评审。
- 高风险表达处理流程经过产品和安全评审。

## 16. 主要风险与应对

| 风险 | 影响 | MVP 应对 |
| --- | --- | --- |
| AI 错误提取记忆 | 用户画像失真 | 候选状态、来源证据、人工确认、版本纠正 |
| 私人内容被公开回答检索 | 严重隐私事故 | 独立公开副本、独立索引、独立检索函数、权限测试 |
| 第三方人物隐私被发布 | 法律和关系风险 | 默认私有、敏感识别、发布前提示、禁止自动发布 |
| 模型供应商故障 | 对话和处理不可用 | 统一 AI 网关、超时重试、供应商可替换 |
| 文件解析漏洞 | 系统安全风险 | 类型校验、隔离 Worker、资源限制、及时升级解析库 |
| 模型成本失控 | 商业模型不可持续 | 配额、上下文裁剪、增量索引、用途分级、调用审计 |
| 克隆声音被冒用或用于深度伪造 | 人格权、诈骗和品牌风险 | 仅限本人建档、随机授权语句、独立公开授权、禁止任意配音和下载、生成审计 |
| 声音样本或模型标识泄漏 | 高敏个人数据泄漏 | 最高敏感等级、私有存储、最小权限、运营默认不可试听、供应商标识加密 |
| 实时语音延迟或弱网中断 | 对话体验不可用 | 流式处理、打断机制、超时、重连提示、默认声音和文字降级 |
| 语音调用成本失控 | 单用户成本过高 | 分钟额度、并发限制、静音检测、分项成本监控和异常暂停 |
| 供应商无法完整删除声音资产 | 用户撤回无法落实 | 上线前验证删除能力、保存删除回执、供应商能力不满足则不接入 |
| 用户过度依赖数字分身 | 伦理和安全风险 | AI 身份提示、现实关系引导、高风险场景退出模拟 |
| 架构过重 | 延迟产品验证 | 模块化单体、PostgreSQL jobs、暂不引入额外基础设施 |

## 17. 依赖与待确认事项

以下事项不阻塞文档评审，但应在开发排期前确定：

1. 现有 iOS App 的登录方式、Token 格式和用户 ID 规则。
2. 首批用户主要位于中国大陆还是海外，以及对应的数据存储地域。
3. MVP 使用的模型供应商、OCR 和音频转写供应商。
4. 当前 iOS App 已支持的文件格式、上传大小和对话协议。
5. 公开数字分身采用匿名访问还是必须登录。
6. 用户是否允许将候选记忆用于私人问答，默认建议只使用已确认记忆。
7. 首轮是否包含哀伤场景；若包含，需要单独完成危机干预和伦理评审。
8. 声音克隆、流式语音识别和流式声音合成使用同一供应商还是组合供应商。
9. 声音供应商是否支持模型删除、公开使用授权、水印或生成来源标识。
10. iOS 与后端的实时音频协议、编码格式、采样率和打断交互方式。
11. 声音样本最低时长、录制引导、活体校验和试听通过标准。
12. 实时语音原始音频的默认留存策略，当前建议不长期保存。
13. Owner 和 Visitor 的语音分钟额度及超额处理方式。

## 18. 最终产品边界

第一版要验证的不是“AI 能否完整复刻一个人”，而是以下闭环是否成立：

```text
用户愿意持续输入
→ AI 能形成用户认可的可追溯记忆
→ 这些记忆能提高本人问答的价值
→ 用户愿意主动发布一部分内容
→ 他人能够从数字分身中获得真实且不越界的知识和经验
```

第一版同时以声音克隆和实时语音作为核心交互能力。上述闭环被真实用户验证后，再扩展家庭空间、关系图谱、视频理解、语音精细化控制和数字传承能力。
