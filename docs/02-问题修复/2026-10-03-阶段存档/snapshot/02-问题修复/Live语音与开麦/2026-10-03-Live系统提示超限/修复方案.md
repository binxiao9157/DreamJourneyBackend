# Live 开场系统提示预算修复

关联 DJ-LIVE-PROMPT-BUDGET-20261003；2026-10-03，用户已授权实施。原始原因见同目录《问题分析与证据.md》。这是开场上下文边界修复，不调整会话保存、收尾发布、主题审核或十分钟结束策略。

## 证据与预算口径

现场返回 system=12749、latest_user=13、asst_prefix=5、total=12767 > 12288；旧实现只限制 32768 字符，并装入全部正式事实。供应商错误没有注明单位，官方公开文档未取得本部署 tokenizer 的精确计数接口。不得把字符、UTF-8 字节与供应商计数混称。

本次引入最终 system_role 的保守 UTF-8 字节预算，默认及硬上限 8192 字节，可通过配置调低。计入角色、风格、规则、JSONL 字段、每条完整事实、分隔符和说明；旧字符限制同时保留。该数值有意低于现场 12288 阈值，为开场输入及包装留余量，但不宣称这是精确 token 计数或保证任意长度后续输入。真实模型/真机验证单独记录。

## 实现

1. 权限、正式事实资格筛选仍使用现有投影；数据库完整内容保持不变。
2. 在最终角色拼装处执行预算选择，沿用维度优先、稳定顺序。整条事实及其主体、否定、时间等限定字段共同进入或共同省略；跳过装不下的一条后继续尝试后面的较小事实。
3. 固定规则明确这只是本场可用的记忆子集，未提供不表示用户没有该经历，无依据时不能编造。即使全部事实都装不下，保留完整规则启动正常交流；固定规则本身超预算则明确拒绝。
4. 按实际选中集合重建 coreFacts、编号、维度引用、coverage 和 contextHash，再绑定最终原文 providerContextHash；不得出现快照说全量但模型只收到子集的假证明。
5. 记录仅含大小、计数、预算口径及哈希的诊断，不记录用户记忆正文。运行配置入口必须实际传递新预算，不只修改一个未使用的常量。

## 验收与边界

- 新增业务反例在旧实现失败、修后同断言通过：大量正式记忆的一句话开场、中文/emoji/转义字节边界、超长单条后仍可选较小事实、固定部分超限、投影不变、子集事实及哈希精确一致、稳定重复绑定。
- 保留主体/否定/强度/时间/注入隔离及权限测试；更新原先“全部事实或拒绝 Live”的测试，明确它已不符合本次容量处理目标。
- 测试实际 API → 快照 → 票据绑定，现有代理和正式记忆资格回归；对最终代码执行 diff 检查。
- 本地预算测试不代表供应商或手机已通过。部署后先验证记忆较多账号的短开场、回复、正文保存、待确认、确认后正式记忆，再开展十分钟场。不能拿 HTTP 101 或小提示成功代替容量边界验收。
- 未选入本场的记忆可能无法在此场被准确回忆；本次不新增检索/RAG，不修改或删除正式记忆，也不通过模型压缩改写事实。
- 历史首轮超时、整理状态错误、SDK 原始错误直出等独立问题不因本次本地修复自动关闭。
