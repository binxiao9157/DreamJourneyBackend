## 产品目标与设计优先级

回响是现有产品内的一个页面，不独立建立另一套视觉系统。优先级为：用户本轮确认的交互与一致性要求 → “记忆档案”和“我的”现有公共样式与组件 → Stitch 的布局及氛围参考。发生冲突时以现有产品一致性为准。

本次不是仅调整整理状态，而是覆盖完整页面：顶部身份与通知、光球、对话状态、回复卡片与记录展开、语音与文字入口、整理结果，以及底部导航、适配和验收。自动状态核对作为必要的配套修复，独立记录证据。

### 布局与操作路径

从上到下为顶部身份栏、光球、统一状态区、回复卡片、操作区，底部是公共导航。光球是主体但不能以占满屏幕为代价压缩关键操作；小屏、大字号和键盘出现时优先缩小光球与装饰留白。

- **默认待机**：顶部显示当前身份；光球安静流动；显示文字输入栏和麦克风入口。不能把示例回复当作用户实际记录。没有会话时不显示“已连接”。
- **启动 Live**：点击麦克风进入现有启动流程，隐藏输入栏并收起键盘，状态区展示连接进度；独立麦克风按钮承担结束动作，图标和无障碍标签明确为“结束对话”，不能误导为单纯静音。
- **Live 进行中**：光球与聆听、等待、回答相对应，回复区域接收现有流式文本；不提供文字发送路径。点击身份或切换页面时沿用已有会话保护规则，不新增隐式停止或权限切换逻辑。
- **结束 Live**：用户点击或现有自然结束流程触发正常停止，动画回落，文字入口恢复，状态区转入三态整理；不因整理尚未完成而锁住整个回响页面。
- **文字回响**：输入栏作为现有文字回响的呈现入口。键盘与发送按钮的具体布局可沿用产品已有组件；提交内容继续走既有业务入口，不与活跃 Live 混发，也不由视图重绘触发发送。
- **输入草稿**：若文字已有未发送内容又开启 Live，不发送、不静默清空；在当前页面和同一身份内恢复输入时保留。跨进程或跨身份草稿能力不在本轮新增范围。
- **连接失败或无麦克风权限**：属于语音启动错误而非整理错误。保留既有错误与权限入口，恢复可用的文字输入，不宣称发生了一场整理失败。
- **查看整理结果**：本场成功后可从状态区域进入待确认记忆，沿用既有确认与正式记忆流程，不因查看结果自动确认。

记录展开建议使用原生可收起面板，显示本场用户与助手的完整文本。它属于查看，不提供对原转写的直接改写入口；Live 活跃时保留明确可达的结束操作。此面板的具体高度与动画属于实施布局建议，不改变已确认的“可展开完整记录”需求。

顶部返回按钮只在当前导航关系确实允许返回时显示，不为照搬截图给根页面增加无意义返回。顶部铃铛仍打开现有通知中心，既有未读提示与权限规则全部沿用。

## 2 已确认交互

| 区域 | 确认行为 |
| --- | --- |
| 顶部身份 | 对应现有“自己 · AI 助手”区域，沿用身份选择、本人与家人权限、记忆归属规则。示例“爷爷的分身”不成为默认业务身份。 |
| 返回与底部导航 | 沿用已有导航目的地及会话离开规则，不能因视图重建丢失会话或改变停止语义。 |
| 右上角铃铛 | 保持现有通知中心，不改为整理结果中心，不新增小圆点或通知派发规则。 |
| 光球 | 蓝天白云般的柔和流动，参考 GPT Live 的视觉感觉；不要求逐像素复制其动画。 |
| 光球下方 | 统一状态区。Live 开启时展示当前对话状态；结束后展示整理状态。 |
| 回复卡片 | 当前回复，最多 4 行；长内容内部滚动，并可展开本场完整记录。 |
| Live 关闭 | 显示文字输入栏及麦克风入口，文字回响继续使用现有能力。 |
| Live 开启 | 隐藏整条文字输入栏，键盘收起；显示独立麦克风按钮。连接、聆听、等待回答、播放回答期间均不可输入文字。 |
| 麦克风操作 | 点击开始，再点击结束，不用长按；结束动作沿用现有流程。 |
| 核实整理按钮 | 移除用户入口，必要的原任务状态查询由系统自动执行。 |
| 真正整理失败 | 沿用既有恢复规则；本轮不增加模型重试次数、不重置预算、不提供新的重新整理能力。 |

Live 的开启状态必须以现有用户会话生命周期判断，不能只看是否正在收到音频。等待回答、短暂静音、连接中均不代表已关闭。停止后按现有关闭流程恢复输入栏，不等待记忆整理完成才允许下一次输入。

## 3 回复卡片与本场记录

1. 短回复完整显示，卡片随内容增长至最多 4 行；达到上限后页面不再被撑高。光球、状态区、麦克风不因持续输出被挤出屏幕。
2. 最大高度按当前字体的 4 行行高及内边距计算，支持系统字号；在小屏和大字号下优先保证文字与操作可达，允许光球缩小。
3. 长回复在卡片内滚动，流式输出默认跟随最新内容。用户手动向上滚动后停止自动跟随，直到回到底部或进入下一条回复。
4. 使用明确的“展开”入口打开本场记录，避免把滚动手势误识别为展开。展示本场用户转写及助手回复；收起只关闭记录视图，不结束 Live、不重置记录或重新提交内容。
5. 记录读取现有权威转写与回复数据，保留原消息身份、顺序和更正语义，不由 UI 再拼装一份可写正文。
6. 视觉截断不截断原文或持久化数据。切换身份时不得显示另一账号或无权访问的会话记录。
7. 新增记录展示仅服务本场，不在本轮扩展为全量历史聊天系统。跨进程后只能展示既有机制实际可恢复的内容，不假定所有助手音频都已有完整文字。

## 4 光球动画

| 状态 | 视觉表现 |
| --- | --- |
| 未开始 | 云雾慢速流动，轻微呼吸。 |
| 用户说话 | 随已有输入音量信号柔和起伏。 |
| 等待回答 | 平稳流转，不伪装成正在播放回答。 |
| 助手回答 | 随实际播放音频的强弱波动。 |
| 正在整理 | 回落为舒缓呼吸，不表现为麦克风仍在采集。 |
| 整理完成或暂未完成 | 安静状态，结果由状态区文字表达。 |

动画只消费状态和经过节流的音量值。不得为了动画新增录音器、音频会话、播放队列或改变 PCM 内容；缺少安全可用的音量接口时先使用状态动画，并明确动态音量响应尚未完成。

幅度需要平滑、限幅，避免突变或闪烁。页面不可见或 App 进入后台时停止渲染；重新显示时恢复视觉，不重新开麦。支持减少动态效果。渲染故障可降级静态光球，不能影响对话或记忆保存。实现时优先使用现有 iOS 渲染能力，本方案不要求引入 WebView 承载整页。

## 5 统一整理状态

用户只看三种主状态，内部的同步、排队、重试、未知、隔离等细分状态保留用于恢复与诊断，不直接全部暴露。

| 主状态 | 使用条件与文案 |
| --- | --- |
| 正在整理 | 保存、同步、排队、处理、已有自动恢复，以及暂时无法核实时。离线或观察超时可用辅助文字说明“暂时无法获取进度，联网后会自动核对”，不能因此判失败。 |
| 整理完成 | 已验证本场发布结果和可访问的结果归属。有新增候选时显示“整理完成，已存入待确认记忆”，提供查看入口；确实没有新增记忆则显示“整理完成，本次没有新增记忆”。 |
| 整理暂未完成 | 同场权威结果明确处理停止或失败，且本轮已有自动恢复已结束。仅在确认正文保存情况后补充“对话已保存，无需重新讲述”；部分保存必须如实说明，保存未知不能承诺已保存。 |

已有可用部分成功发布时按完成处理，辅助说明“少量内容暂未整理完成”，不得因少量遗漏将全场显示失败。不能仅依据任意候选总数大于零判断本场完成，必须核对本场身份与发布结果。

新 Live 开始后，状态区优先属于新会话。上一场晚到结果只更新其自身记录，不覆盖当前连接、聆听或回答状态，也不修改通知中心规则。当前会话终态显示不被旧版本响应倒退；不同场次、账号、档案之间不得共享终态判断。

## 6 移除按钮后的自动核对

现有按钮调用 verifyStatus 启动只读观察轮，读取候选状态；并不创建新整理任务。现有新协议恢复路径与旧候选查询路径并存，不能把按钮方法简单复制为新协议的统一查询入口。

实施目标：

1. 结束本场后自动观察原任务；重新进入回响、App 回到前台、网络恢复时，对未核实的相关任务进行有界只读核对。
2. 按原任务实际协议选择状态来源。绑定账号、档案、productSessionID 及原 session/Source/任务坐标，保持既有访问校验。旧提取任务失败不得在新发布结果已成功时被直接当作本场最终结论；冲突先核对权威来源，不拼凑成功。
3. 优先复用现有统一观察器；同一任务同时最多一个有效观察轮，合并前台、网络恢复、页面进入等并发触发，丢弃过期响应。
4. 只读观察的时间窗口与模型业务重试预算分离。一次查询窗口耗尽仅结束该观察轮，不结束后台任务、不清除恢复坐标、不标记整理失败。
5. 可见页面下尚未终结的任务需在有界窗口后继续低频自动核对，避免沿用一次 180 秒即永久不更新的行为；后台不维持无限轮询。具体间隔、退避及每轮上限在实现前结合已有观察器确定，并记录在修复文档与测试中，不能通过放大全局超时解决。
6. 网络或权限不可用时暂停请求并给出准确辅助说明；重新具备条件后重新核对。查询不能额外触发模型、重放未知写、重新提交 end/ACK/admit 或创建替代任务。
7. 后台明确失败时仍不自动增加新的业务重试。用户开始新 Live 不等于重试上一场。

这部分是客户端状态核对修复，需在 02-问题修复 留下独立的原因、改动与红绿证据。本方案不宣称现有状态冲突的全部首因已被证明。

## 7 实施范围与顺序

1. 记录实施前源码指纹、工作区状态和当前短场至候选的基线；保留既有修改，不重置代码。
2. 先建立页面呈现状态与场次绑定，补“迟到成功、旧失败、观察超时”的回归反例，再修复自动状态核对。
3. 以现有 EchoViewController 为接入点拆出独立展示组件，替换布局、回复卡片、输入区和光球；不整体重写 Controller 或保存协调器。
4. 输入、麦克风、身份、通知、导航动作继续调用现有业务入口。保留重要自动化标识；移除核实按钮后同步更新相应验收，不能用假按钮维持旧测试。
5. 冻结最终源码与构建，完成受影响回归及同版本短场、长场验证，再给出分层状态。

保存链路不得因布局、卡片展开、滚动、动画帧、页面显示或销毁而重复开始或停止。无后端合同变更需求时不修改后端；若实现发现必须修改，先记录具体缺口及最小范围，与用户讨论。

| ST-03 | 断网、查询超时、前后台切换、重复页面进入不产生假失败、并发查询风暴或新增模型业务请求。 |
| ST-04 | 部分发布、无新增、明确失败、正文部分保存及保存未知分别显示准确，不笼统承诺安全保存。 |
| ST-05 | 本场已发布但候选暂时无法读取时自动核对，不读取他场数量冒充成功；确认后的既有正式记忆不重复发布。 |
| KEEP-01 | 同版本独立短场先通过，验证原文同步、尾批、候选读取、审核、正式记忆与重建读取，再执行逻辑约 10 分钟长场。 |
| KEEP-02 | 长场之后再验证短场，确保页面和状态改动没有影响短场；保留原有幂等、权限、恢复、音频回归。 |

测试须检查真实产品入口、状态来源和持久化结果，不能仅以文案快照或伪造的成功状态验收。已有本地模拟模型测试不替代真实供应商交互。

### 8.2 用户后续主动发起的真机验收

本地工作不得因为没有手机而暂停。真机、真实 Provider、部署各自记为 NOT_RUN，直到实际执行。

真机按同版本短场 A → 约 10 分钟自然收尾长场 → 短场 B 检查。每次长场前短场均需独立通过。自然收尾沿用当前已约定规则，不要求在第 10 分钟强制切断，也不恢复旧 20/40/65 分钟压力测试要求。

验证文字实时显示、Live 声音、光球响应、输入隐藏、通知中心、结束后的三态，以及本场待确认读取、确认后正式记忆和冷启动回查。至少覆盖一次长回复展开和一次返回前台后自动获知整理结果。自动音频注入与真实麦克风/扬声器声学验收分开标注。

遇到可恢复的整理错误，保留首错并按已有授权继续观察同场收尾和兜底，不立即制造新场次掩盖失败；不得重置预算或人工改结果使其通过。

## 9 实施结构建议与回退

展示组件可按身份栏、光球、状态区、回复卡片、本场记录面板和输入区拆分；命名服从现有工程。视图只输出用户意图、消费状态，不持有新的业务真相。

- 会话、账号权限、正文与发布状态继续由现有协调器和服务持有；页面使用带场次身份的展示模型。
- 不在本轮修改模型提示词、候选合并标准、事实分页、尾批触发、自动自然收尾规则或正式记忆确认机制。
- 新 UI 与状态核对修复应能分别审查与回退。若光球性能不达标，先降级视觉，不能删除音频或保存检查来换取流畅。
- 动画音量读取不保存新音频；诊断只记录必要状态与脱敏关联，不为 UI 增加原文日志。
- 验收时记录动画开启与关闭的帧流畅度、主线程与音频异常情况；未经测量，不声称动画无性能影响。
